# Locked tooling for clean legacy proof verification

The compatibility lanes and the aggregate verifier are separate jobs. On head `ca77f9ee0a753b24d17a555048a0908aa5dff4f8` (run `38873517372`, attempt 1), all 18 consumers passed, but the clean aggregate job failed loading `semver` from `root-registry-supply.cjs`. Lane success does not replace aggregate verification.

A conservative literal import audit covers 21 source files, including lazy retained-normal-AFS paths. The only actual external verifier dependency is `semver`; AFS library consumer imports in generated probe strings are not aggregator imports. The dedicated private manifest pins `semver` to the repository's existing exact development version (7.8.5), with a real Bun 1.4.2 lock. The CLI publication lock is deliberately not reused: it includes unrelated workspaces/build tooling.

The local setup action selects actual Node 22 and Bun 1.4.2, copies the tooling manifest, lock and official-registry configuration into a fresh directory outside the checkout, then performs a frozen, ignore-scripts install there. It never installs root product dependencies or copies existing node_modules. Preparation rejects pin drift from the repository authority. It exposes one explicit isolated NODE_PATH and a verifier-only provenance preload.

The preload only asserts facts; it does not replace module resolution. It checks actual Node, original/copy manifest and lock bytes, exact semver identity, and semver resolution from the validator's own require scope against the isolated package directory. Host-resolved or shadowing dependencies fail rather than silently substituting. It records source/tool hashes, actual Node executable and resolved semver entry. The original verifier and its arguments, archive/raw/source checks, exit behavior and all 18 required lanes remain intact. Provenance is not an acceptance claim.

The clean Legacy aggregate job and the clean stable promotion guard use the same setup. The candidate finalizer already installs locked root dependencies and keeps its existing setup. Only the root compatibility command receives the isolated NODE_PATH/preload; unrelated release checks are unaffected. The successful aggregate artifact retains the tooling receipt alongside its original compatibility evidence. Promotion readback does not mutate accepted inputs.

Small tests use real frozen Bun installation and a clean Git/source scope without ancestor node_modules. They run the existing synthetic 18-lane verifier fixture through the real CLI, reject tampered raw evidence and missing dependencies, and verify that host package resolution cannot replace the declared tool. These are tooling contracts, not real CI consumer or deployment acceptance; the new immutable head must still pass its natural workflow.
