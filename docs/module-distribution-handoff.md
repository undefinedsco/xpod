# 模块分发迁移交接

本清单按 2026-10-10 的开发状态划分落实责任。技术契约以 [模块分发规范](module-distribution.md) 为唯一来源；本清单只记录任务边界，不复制格式或维护另一张运行注册表。第一阶段实现见 PR #43，提交 c3ab49d2。

| 当前任务 | 当前状态与交接理由 | 由对应任务落实 |
| --- | --- | --- |
| 开发加速 | 已完成 CLI 核心迁移、公开 client 接口、独立构建/安装门禁和通用模块安装器 | 公共分发规范、tag 规则、CI/CD 路由与独立发布流程、交接协调；保留 CLI 实现单一来源 |
| SolidFS 模块 | 正在核对固定提交的镜像、原生和挂载证据，避免改动正在验收的产物 | AFS 客户端及真实 helper 的自包含平台包；afs tag、manifest/完整库存、安装产物真实挂载验收；CSS 侧 SolidFS 存储/授权 adapter 留在 CSS 边界 |
| Base Xpod 模块 | 服务/桌面、认证与共享持久化仍在改动；主工作区发布配置也有未提交变更 | CSS/API 与共享服务的依赖边界、按需运行计划、Gateway/readiness/生命周期；桌面消费约定产物；提供服务启动与产物验收契约，公共 CI/CD 由开发加速统一实现 |
| Matrix 模块 | 成员关系与消息存储链路正在修复和原生集成验收 | 明确 API 路由、共享业务和 CSS 授权/存储 adapter；去掉客户端对服务实现的穿透；先列独立交付需求，再决定是否登记独立下载能力 |
| Fabric 模块 | VM 生命周期、Pi 执行与共享模型/ORM 正在改动 | 区分 API 控制面、共享运行协议与重型 VM/Pi 后端；按能力注册后端、保持通用接口；后端关闭时不加载/启动；先明确独立交付边界，避免让 CLI 默认携带重型依赖 |

各任务先处理自己尚未冻结的接口与依赖声明。已经启动的验收继续针对原提交/摘要；拆包改动进入后续候选，不覆写正在验收的 SHA、tag 或产物，也不自动中断原作业。

落地回报应给出：归属/包边界、拟修改文件、依赖与启动面、发布标识、现有证据是否继续有效，以及尚未满足的宿主契约。只有可获取的真实产物通过相应验收后，才能宣称模块可下载或真实功能可用。公共规范的缺口回报到开发加速任务，由一个入口修订，不在各模块维护平行规范。
