# 多凭据的额度与模型目录

## 调整步骤

复用现有额度卡、凭据池和模型目录，不新增服务或依赖。先以回归覆盖多凭据结果和模型顺序回退，再改状态归属与调用策略，最后按模块、共享组件及浏览器布局验收；供应商配置通过适配测试核对，不逐家重复完整登录流程。

## 额度

- 查询结果、进行中状态和错误仅放在页面 React 内存中，不写 Pod、数据库或浏览器存储。页面卸载后丢弃，下次进入按需查询。
- 订阅、API Key 与其他接入方式合并为同一凭据列表，额度直接显示在所属凭据行。单条与多条均使用紧凑摘要；查询与重置时间放在信息图标打开的浮层中，不改变凭据行高度。
- 每条凭据独立显示；调整优先级或停用不会把其他凭据的结果换上新标签。
- 多凭据时提供“刷新全部额度”，查询当前供应商各接入方式的启用凭据；每条仍可单独刷新，停用项可手动检查。
- 同一凭据的进行中请求不重复发出。一条失败或未完成不阻塞其他条结果。
- 不求和、不根据用户填写的名称合并账户。当前没有可靠计费账户标识，多个 Key 或 OAuth 凭据可能共享额度。
- 展示成功结果的查询时间；失败、未查询、查询中和接口不支持分别显示。

## 模型

- 界面暂按同名模型等价处理：同一供应商、同一 model id 只显示一行，不按订阅/API Key 重复展示。勾选展开该模型所有可用接入路径，取消选择移除所有同名路径；仅打开页面不会改写已有选择。同步与运行仍保留接入方式信息。

- 常规供应商按产品类型、端点和协议兼容模式分组；组内按优先级尝试启用凭据，取得成功响应即停止。
- 成功的空模型列表仍是有效响应，不作为认证失败切换凭据。
- 同一产品多个端点均参与同步，结果去重取并集，向现有共享目录一次性保存，避免逐次写入互相标记模型缺失。
- 自定义服务沿用每连接实例的独立目录。当前导航与 Pod 数据都以连接实例区分，不跨实例合并。
- 显式指定凭据时仅查询该条，用于新增/更新连接后的定向同步。
- 成功同步后，以实际使用的凭据版本标记该凭据健康，允许 Gateway 路由；OAuth 刷新后使用新版本。健康状态持久化失败应直接报告，不能重新请求供应商或错误切换备用凭据。
- 某产品有端点查询失败时，不覆盖该产品的持久化目录；界面保留旧模型并提示部分失败。其他完整成功产品仍可保存。
- 模型目录与模型选择共享，不宣称目录中的每个模型都已通过所有备用凭据的权限验收。

## 验收范围

- controller：优先级、首成功停止、回退、定向请求、目录并集、部分失败与 custom 隔离。
- Panel / 凭据池 / 额度卡：全部与单条刷新、并行成功失败、停用、结果身份隔离、模型部分失败保留。
- 供应商 client / adapter：沿用参数化测试核对产品、认证、端点与响应解析。
- Web 组件：用真实组件和 fixture 验证桌面、390px 手机、长名称、查询中及交互，不声称为真实账号或供应商验证。
