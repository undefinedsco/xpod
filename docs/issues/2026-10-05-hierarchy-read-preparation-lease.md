# Hierarchy read preparation outlived the Local lock lease

Normal Matrix acceptance exposed two failure classes while preparing 0.4.24. The initial PUT returned HTTP 500 in `recovery-matrix-normal1-private.log`, with a preceding `WrappedExpiringReadWriteLocker` error, `Lock expired after 6000ms`. A separate normal run reached sync but stalled before all 63 expected events were returned; its private log contained 34 lock expiry messages on ancestor containers. Another backlog failure recorded four Local QLever requests reaching their unchanged 60000ms request budget. These observations are retained separately: lock lifecycle evidence does not by itself establish the cause of the native query stalls.

The Local configuration wraps its resource locker with a 6000ms lease. CSS renews representation read leases when the returned stream is read. `HierarchyLockingResourceStore` acquired root-to-target read locks through that helper, so an acquired ancestor had no renewal while awaiting another lock or the source representation. Its mutation path already maintained acquired leases during preparation. Expiration could reject a live read before a representation was available, releasing its ancestor protection while the inner asynchronous operation continued.

The regression uses the actual CSS expiring locker and advances a delayed preparation beyond its original lease. Before the fix it fails with `InternalServerError: Lock expired after 6000ms`; the unchanged idle-response expiry case passes. The adapter now maintains acquired read leases only during preparation. Once returned, the existing CSS stream wrapper handles consumption renewal, idle expiry, stream end/error/close and lock release. A shared attempt state prevents a late inner acquisition from publishing a representation after an ancestor failed. Legacy storage initialization still occurs only after the rejected read acquisition has released its locks.

Focused regression evidence: initial RED exit 1 (one failure, seven passes); fixed hierarchy and legacy-version suites exit 0 (21 tests). Tests cover slow preparation, waiting for an inner lock, original idle expiry, competing writes, rejection, stream error/close, timer cleanup and late acquisition after lease loss. This is a storage adapter lifecycle fix, without Matrix/ORM identity changes, a new dependency, or longer configured timeouts.

The unmodified complete run `sol-recovery024-frozen-normal-full1` was started before this source fix and failed in a backlog PUT (runtime 30 passed; lite 162 passed, one failed, 16 skipped). Its process was still completing when the new source landed, so it is historical diagnosis evidence, not a frozen-source acceptance run. Focused tests do not replace the two complete post-fix gates, exact-source RC checks, or stable publication. The Root checkout has neither this hierarchy component nor its tests; this change is confined to the release candidate.

Two subsequent frozen-source complete gates actually exited 0: `sol-recovery024-readlease-afterfix-full` and `sol-recovery024-readlease-precommit-full2`, each with runtime 30 passed, lite 163 passed/16 skipped and full 63 passed. The normal Matrix chain passed in both. The intervening asset stress failure, bounded diagnosis and remaining release gates are recorded in [the dated local verification](../testing/2026-10-05-release-024-local-verification.md); no test timeout or retry behavior was changed.
