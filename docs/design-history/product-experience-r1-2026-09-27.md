## 2. 产品任务、信息层级与文案

Xpod 让用户理解并控制资料的保存、应用连接和运行基础；桌面端承担本机服务、网络、AI 接入和配置。LinX 承担日常工作体验。Xpod 不新增聊天首页、任务流或网盘式默认首页。

北极星“个人日志合并在一起，就是整个文明的历史”指导长期取舍；工作区先解决今天的操作。界面不以永久保存、全天在线、默认本地推理、永不外发或代替用户做主作为未经证实的承诺。

每个内容页按以下顺序组织：当前对象和任务标题 → 结论及影响 → 一个当前主要动作 → 内容/字段 → 按需展开的专业详情。无异常时不制造警告区；诊断入口始终可达。一个区域可有次要动作，但不能把保存、测试、删除同时做成同等主按钮。

中文界面统一使用“状态 / 网络 / AI 接入 / AI 配置 / 设置”；英文使用“Status / Network / AI Connections / AI Config / Settings”。Account 首次说明为“管理账号”，WebID 首次说明为“WebID 身份”，Pod 首次说明为“Pod 存储空间”，后续保留准确名称。产品文案由应用的现有国际化层提供；不新增 SDK 硬编码文案。

原始资料、派生索引、提供方凭据、Xpod API Key、机器凭据分别命名；不用“数据”“连接”“退出”包办不同对象。身份、Pod、机器切换后的标题与动作范围必须同步，旧请求不能覆盖新对象。

## 3. Shell、导航与 URL

### 3.1 单一 Shell

桌面 Rail 顶部是身份入口；中部依次 Status、Network、AI Connections、AI Config；底部 Settings。无可展示身份时使用中性入口，不伪造头像或凭此触发登录。List 只放可选主题和必要状态摘要，Content 才展示结论、字段和动作，不增加第二层一级导航。

以下是本轮**目标 URL 契约**，不是从当前路由实现读出的事实。具体主题统一采用以下路径；已有安全回调和 CSS 路径不纳入改名。AI Connections 的内部选择形式保留其既有契约，Shell 只接入顶层入口。

| 工作区 | 默认/主题目标 |
|---|---|
| Status | /status/overview；/status/services/gateway、/status/services/solid-server、/status/services/api-server；/status/logs |
| Status · Index | /status/index/overview、rdf、fts、vector、retrieval-points、cache、slow-queries、benchmark（后七项接在 /status/index/ 下） |
| Status · Usage | /status/usage/overview、storage、bandwidth、ai、index-storage（后四项接在 /status/usage/ 下） |
| Network | /network/overview、endpoints、addresses、domain-dns、https、tunnels、p2p、diagnostics（均接在 /network/ 下） |
| AI Connections | /ai-connections；API Keys 与具体 Provider 选择复用 AI Connections 路由契约，不产生第二份提供方详情页 |
| AI Config | /ai-config/model-assignments、document-processing、search-indexing、index-lifecycle（均接在 /ai-config/ 下）；默认 model-assignments |
| Settings | /settings/pod、identity-access、storage、runtime、cloud、advanced（均接在 /settings/ 下）；默认 pod |

新打开工作区入口进入 Status；明确 deep link 优先。切换 Rail 保留本次窗口内每个工作区上次选中的合法主题；完整 URL 可刷新、可返回。不把跨账号或跨 Pod 的上次对象直接带入新身份。缺少某个主题的能力时，该 deep link 显示对应原因，不跳到看似成功的其他页面。

## 4. 页面权限与事实边界

| 页面/操作 | 所需来源 | 不得据此要求或推断 |
|---|---|---|
| Status 的 Account 管理面、CSS Account 页面 | CSS Account | 不启动无关 WebID 恢复，不要求已有 Pod |
| 本机 Network、Runtime 等管理动作 | 已有受保护本机/宿主 authority | “本机”不等于匿名管理权限；不要求无关云账号 |
| AI Connections、Pod 持久化的 AI Config | 有效 WebID 与准确目标 Pod 的访问能力 | Account 成功不构成 Solid 授权；API Key 不构成管理权 |
| /settings/pod 的清单及创建编排 | Account 与该管理动作所需的机器/创建授权 | 零 Pod 不能挡在门外；管理成功不构成 Pod 内容读写授权 |
| Pod 内容、授权资源与持久化配置 | 既有 Solid 授权 | 不用机器控制权或 Account token 替代 |
| 机器控制/后台运行 | 9/19 定义的控制与宿主能力 | 浏览器不持有 service/node 管理凭据 |

同一页面需要多种能力时按区域消费，不合并成新的“全部就绪”会话。Status 中依赖 Pod 的用量区域可显示资源恢复入口，其失败不遮住已授权的服务状态。Account/WebID 两方分别呈现自己的账号、阶段与退出结果。

沿用 canonical：Account 四态、WebID 五态、Pod 八态；本文的“长等待”“上次数据”“未支持”是展示或能力说明，不新增领域枚举。Account 错误不能被改写成 anonymous；WebID/Pod 失败不能清掉另一方会话。原始 WebID 字符串按领域规范比较，不能以展示格式化参与身份匹配。

## 5. 认证、Pod 与任务续接

### 5.1 场景和容器

| 场景 | 固定展示合同 |
|---|---|
| WebID 或简短 Account 登录、恢复、回调 | 280×400 compact 基线；主题画布铺满，16px 内边距；一份 body，无内嵌白卡/遮罩 |
| Xpod Web Account | ≥900px 左产品说明、右表单；右表单最大 448px；<900px 同一 body 单列，说明压缩到必要上下文 |
| 注册、完整 CSS consent、独立 Account 入口中的首次 Pod/Pod 管理 | Account 文档流程，不能强塞 compact；文档单一纵向滚动，不套 Card/ScrollArea |
| 工作区内的 /settings/pod | Settings Content 承载同一 Pod 管理 body；保留 Shell，不嵌套 Account 文档外框 |
| App 承载 Account 文档 | 首次默认 1040×760，最小目标 640×560，受系统可用空间夹限；由宿主路由 owner 选择 |
| 正常短表单 / 长错误或 200% 字体 | 正常无需额外内滚动；内容变长允许一个宿主内容滚动区，保证错误、主动作、返回都可达 |

Pod 管理的容器由显式入口场景决定：Shell 内访问 /settings/pod 使用 Settings Content；从注册或 consent 进入的独立 Account 场景使用 Account 文档。宿主/路由 owner 持有并在刷新、续接时保留场景标记；它只是展示输入，不是认证凭据或任意外部 returnTo。没有独立场景标记的 /settings/pod 按 Shell 渲染。两种场景共用 body 与创建事务，完成后返回各自经验证的发起位置。

本文件中的 280×400、1040×760、1180×800 及最小窗口尺寸，均指宿主逻辑像素窗口 bounds；断点与内容间距使用内容视口 CSS px。原生标题栏与安全区占用从可用内容扣除；不得用固定内容高度遮住操作。

宿主唯一决定窗口几何；业务 body 不调用 IPC，不通过 localhost、视口大小或登录状态猜测认证场景。用户调整过的同类窗口尺寸优先保留；切换场景只应用对应窗口约束，不反复重置。浏览器认证对话框按实际可用视口夹限，不伪装成桌面窗口。

### 5.2 从注册到创建 Pod

1. 注册表单仅请求 Account 真实必填项。Account 显示名称若服务要求则保留；Pod 名称、机器、存储选择不混进账号注册。
2. 注册完成进入 Account 页面，反馈“账号已创建”；不调用 Local prepare 或自动创建 Pod。只有权威清单确认无绑定才显示“还没有 Pod”。
3. 用户进入 /settings/pod，选择“创建 Pod”。可选位置来自已支持的 Cloud 与本人有管理权的机器；展示部署方式、保存位置和前提，不默认替用户选择未授权机器。
4. 选定机器若 Xpod 已停止，明确呈现“启动 Xpod”及影响；启动后等待真实健康结果。无法确认状态时先恢复读取，不当作已停止或已就绪。
5. 创建确认展示目标位置、目标身份/归属信息和名称等真实必要字段。只有明确点击“创建 Pod”才提交；同一事务沿用 canonical 的幂等标识。
6. 区分“创建请求已提交”“Pod 已创建”“绑定已确认”和“Pod 已就绪”。创建/绑定结果由目标 owner 与权威记录证明；“Pod 已就绪”还须满足 canonical：精确 WebID × storageUrl 与会话一致，且有实际鉴权读写命中该 Pod 的证据。仅有 Account 时只展示已确认的管理结果，不把资源验证设为注册成功的前提；机器在线、目录存在或接口 2xx 都不足以证明资源就绪。
7. 超时、刷新或重复进入先查询原任务与权威清单；不能通过重注册、换名称、创建替代 Pod 来恢复。“取消等待”不表示服务端创建已撤销。

已有 Pod 不可达、读取失败、缺 owner、身份冲突各有原因和恢复动作；缺 owner 只有权威创建记录或已验证控制权才能支持修复，不猜归属。多 Pod 明确选择，不默认第一个。

“绑定已有 Pod”的证明协议仍由 9/19 §4.2 待定义，属于 §11 的单独依赖。当前先提供禁用入口与可见说明“此部署暂不支持绑定已有 Pod”，不要接受一个 URL 后显示绑定成功；协议缺口不阻塞已支持的显式创建流程。

### 5.3 授权与返回

Consent 展示应用、实际请求权限、WebID 和目标 Pod；无 Pod 时提供“前往 Pod 管理 / 取消授权”。去管理只保存有时限、绑定当前 Account 与原 interaction 的安全续接上下文，不自动创建。回来后重新读权威绑定和健康结果；账号切换或事务失效后开始新的合法流程，不续用旧授权。

WebID 登录复用 Inrupt；CSS 决定是否要求 Account 登录。AI Connections 不嵌入另一套 Account 密码表单。完成后回到合法发起任务及所选对象，不无条件跳 Status。密码、令牌、provision code 不进入 URL、日志、通知或普通持久化表单草稿。

## 6. 公共状态、反馈与动作

### 6.1 等待与恢复

首帧先应用正确主题。首次恢复 <300ms 可保留稳定画布避免闪烁；≥300ms 必须显示具体阶段，例如“正在恢复 WebID 会话”或“正在读取 Pod 绑定”；≥10s 增加“仍在等待”、安全返回/查看详情，只有领域规则允许时才提供重试。这些只是展示阈值，不能把 pending 改成 anonymous、重启 OIDC、重复创建或取消远端操作。

普通刷新保留上次有效内容、时间与“更新失败/正在更新”标记。不要清空全页再 skeleton；身份或对象已切换时不得继续展示前一对象的敏感内容。请求返回与当前对象不符则忽略，由当前 authority 重新读取。

| 状态 | 用户可见表达 | 可用动作 |
|---|---|---|
| 已确认空数据 | 说明尚无什么，不使用故障文案 | 存在且授权的创建/连接动作 |
| 未配置 | 缺失项与影响 | 去对应配置，不伪造测试成功 |
| 未支持 | 当前部署/宿主不支持的能力与原因 | 可保留有说明的禁用入口，不显示可执行假按钮 |
| 能力未知/读取失败 | “状态无法确认”，保留可信的上次时间 | 重查来源或诊断；不显示零额度、零资料 |
| 无权限/会话失效 | 指明对象与缺少的权限/会话 | 合法的授权、重新登录或返回；不影响无关 authority |
| 已保存 / 待应用 | 分别显示保存和应用阶段 | 需要时给明确重启/重建动作 |
| 失败/部分完成 | 哪一步成功、哪一步失败、对谁有影响 | 重试失败阶段；结果未知先查原任务 |

### 6.2 表单、取消与破坏性操作

字段有持久标签、单位/范围和必要说明。校验在触碰/失焦或提交后显示，确认密码不在首次输入主密码时误报。保存中防重复；服务器保存失败保留安全输入。成功 inline 反馈与当前操作相邻，不靠瞬时 toast 作为唯一结果。

未保存修改离开页面时，显示“放弃更改并离开 / 继续编辑”；不默默保存，也不阻止无编辑的导航。普通可逆保存不加确认。删除资料、撤销正在用的凭据、停止服务、覆盖客户端配置、重建索引等按实际影响在提交前说明目标、影响与能否恢复；确认按钮写具体动作而非“确定”。

每次仅一个主模态。Esc 关闭可关闭的弹层并恢复触发点焦点；提交进行中若允许离开，明确只是停止等待，不能将关闭弹层视为取消已提交操作。删除成功才移除列表记录；读取失败不清空列表。没有后端撤销能力时不提供假的“撤销”。

Enter 提交当前表单；普通更新用 polite live，阻断当前提交的错误才 assertive；日志流不逐行播报。焦点落在错误摘要或首个错误字段，刷新不抢焦点。动效 120–180ms；reduced-motion 去除过渡，进度仍有可读阶段文字。

## 7. 各工作区的实施合同

### 7.1 Status：现在能否用，问题在哪里

首屏固定顺序：实例/部署上下文 → 有来源与时间的总体判断 → Gateway、Solid Server、API Server 三行服务 → 推荐访问地址及适用范围 → 按需出现的异常与下一动作。未观察到的依赖不折算成“全部正常”。

服务详情呈现状态、最近检查、端点、版本/进程与依赖、近期错误及日志入口；重启明确具体服务/整个 Xpod 的作用范围。Logs 用来源、级别、时间、文本四个独立筛选维度，明确历史/实时状态；复制或导出只有实际支持且完成脱敏时可用。

Index 的 Overview、RDF、FTS、Vector、Retrieval Points、Cache、Slow Queries、Benchmark 保留观测入口；持久策略去 AI Config。未支持的观测按 §6 表达。Usage 明确 Account/Pod、周期、统计单位与更新时间；资料与索引占用分开。费用、额度、模型细分必须来自观测，缺失不写 0。

### 7.2 Network：配置与实际可达分别可见

保留 Overview、Endpoints、Addresses、Domain & DNS、HTTPS、Tunnel Profiles、P2P、Diagnostics。Overview 先给推荐地址、适用设备范围和最近检测，再呈现其他地址。

Endpoints 显示 canonical URL、API、Solid、issuer，并有复制/打开；Addresses 按本机、局域网、公网分组，标记观测时间。传输别名不能替换 canonical WebID/Pod 身份。托管 canonical 地址只读并说明来源。

Domain、HTTPS 与 Tunnel 编辑区分别显示“配置值”和“当前观测”；保存提示不能写“已连通”。切换隧道时说明旧/新配置且仅一个处于活动状态；高级字段折叠但可键盘到达。运行配置秘密只写入，不回显原值。P2P/诊断能力按实际返回显示，不为填满页面制造按钮。

### 7.3 AI Connections：接通服务商，再让客户端使用

List 保留 API Keys 和 Provider，不加含义模糊的 All。Provider 详情按顺序：当前连接与可用性 → 该 provider 支持的连接方式 → 可用/选中的模型 → 有来源的用量/额度。连接保存、连接检查、模型发现是不同结果。OAuth/浏览器导入/本地端点只在对应 connector 支持时出现。

Xpod API Keys 页按密钥展示名称、作用对象、启用状态和可用统计；创建、停用、恢复、删除依据已有产品行为。提供方密钥用于上游连接；客户端拿到的是 Xpod endpoint 与 Xpod API Key，不把上游密钥填给客户端。

产品级 Xpod API Key 的跨设备恢复材料按 AI Connections canonical；共享 hash-only 验证契约不变。恢复/复制只对被授权对象执行；默认遮罩，用户明确动作揭示/复制。运行秘密和提供方凭据不继承这一展示权限。

客户端接入：选择真实支持的客户端 → 预览目标文件/字段和覆盖影响 → 明确应用或复制手动配置 → 展示写入结果；只有真实连接检测才能说“已验证可用”。能自动恢复旧配置时说明恢复方法，不能时提供可执行的手动回退说明；不伪造一键撤销能力。缺原生适配时提供准确手动配置，不展示失效的“自动配置”。

### 7.4 AI Config：为用途选择模型

保留 Model Assignments、Document Processing、Search & Indexing、Index Lifecycle。选项复用 AI Connections 的连接/模型事实，不复制凭据表单或重新发明模型目录。

Model Assignments 仅呈现已有真实消费者的角色；每行显示用途、继承默认/覆盖、模型及 provider、可用性和恢复默认动作。保存使用领域模型标识，不用 display name 充当 ID。Cloud embedding 只能来自受支持目录，不能提供任意自填 endpoint/model 的假入口。

Document Processing 只放处理策略，不重复角色选择；Search & Indexing 展示 FTS/vector/progressive 等真实支持策略及适用范围，自动选项说明实际来源，embedding 维度只读推导。改变模型/索引策略提示旧索引影响，不自动重建。Index Lifecycle 明确区分“保存配置”和“保存并安排重建”；仅能力支持时给后者。重建阶段、失败和恢复须有任务依据，原始资料不因索引重建被删除。

### 7.5 Settings：明确对象后改变配置

| 主题 | 首要信息和动作 | 边界 |
|---|---|---|
| Pod | 权威清单、当前目标、位置与健康、显式创建/选择/恢复 | /settings/pod 对有 Account 管理能力的零 Pod 用户可达；内容访问另验 Solid 权限 |
| Identity & Access | 管理账号、WebID、可管理的应用授权分别列出；准确命名退出/撤权 | 不暗示切账号自动获得原 WebID 的 Pod；撤销不收回已复制资料 |
| Storage | 资料位置、原始资料/索引用量、实际可用的备份/导出/迁移路径 | 按能力显示范围、目标、验证结果；不支持时如实说明，不承诺所有应用数据无损迁移 |
| Runtime | 启动、自启动、自动重启和允许的配置；保存/重启结果分开 | 健康详情去 Status；手动停止不得立即被自动重启策略抵消 |
| Cloud | 当前部署支持的管理能力与连接关系 | 不适用部署可隐藏 List 项，直接访问显示原因；不强迫 Standalone 加云账号 |
| Advanced | 日志保留、受允许的高级配置、脱敏诊断 | 不新增任意环境变量或任意命令编辑器；秘密只写 |

资料删除、空间删除、移除本机副本、卸载和退出是不同任务；没有领域能力定义时，不因本节列出 Storage 就新增破坏性入口。

### 7.6 跨模块交接

| 从哪里到哪里 | 带什么 | 完成后 |
|---|---|---|
| AI Config → AI Connections | 缺少的 capability/角色说明、合法返回目标；非敏感选择 | 返回后重新读取模型可用性，不自动替用户覆盖角色 |
| AI Connections → 客户端配置 | 用户选定 Xpod key/模型范围；秘密不经路由参数传递 | 显示配置与验证两种结果，保留原 key 选择 |
| Status → Network/Runtime | 明确异常对象和目标主题 | 回到原状态详情并刷新观测，不把保存视为恢复成功 |
| Index 状态 → AI Config | 目标 Pod 和配置主题 | 保存后回看任务/索引状态；不隐式重建 |
| Consent/资源入口 → Pod 管理 | 领域允许的 Account/interaction 续接 | 重新校验身份、目标和绑定；只恢复仍合法的原任务 |

## 9. Logo、托盘与生命周期

### 9.1 资产合同

品牌源资产在 [homepage/public/brand](../../../homepage/public/brand/README.md)。由一个资产负责人导入产品资产位置并记录源文件与校验值；不要求产品运行时依赖另一个仓库，不由各页面复制一份几何。

| 用途 | 输入与处理 |
|---|---|
| App / Dock / 安装包 | xpod-app.svg/png 墨紫底留缝折角；固定品牌色，系统包装只做规定的安全区与格式适配 |
| 产品配对展示 | xpod-app-light.svg/png；16/24px 使用同名专用小尺寸资源 |
| 内容单色符号 | xpod-symbol.svg；按主题用正文/操作色；固定底图场景可用 ink/paper 版本 |
| macOS 菜单栏 | 从单色标生成透明黑色 alpha template，16/32px，约 2px 视觉安全区；由系统处理明暗，实施时验证小尺寸轮廓 |
| Windows / Linux | 由桌面资产 owner 按已有平台链生成透明底和所需缩放尺寸；无 tray 能力时保留窗口入口，不虚构菜单栏 |
| 历史 Logo | 旧资源及探索稿保留，切换引用；金唱片、盾牌等旧说明不再作为新图标目标 |

16px 主符号不承担所有状态编码。异常/降级/未知可叠同一种单色关注标记，精确状态由 tooltip、菜单首行与逐服务行表达；不增加红绿橙点，不把网页 SVG 的存在算作系统打包完成。

### 9.2 托盘内容

首行为 Xpod 及整体运行摘要；随后逐行 Gateway、Solid Server、API Server 的状态文字；再给五工作区入口、权限允许的启动/停止/重启动作，以及按 §9.3 实际宿主能力命名的退出动作。具体服务与整体操作区分，菜单与 Status 复用同一观测来源和时间。

状态文字示例：“3/3 服务运行正常”“正在启动”“部分服务不可用”“服务启动失败”“服务已停止”“状态无法确认”。3/3 只描述服务健康，不声称公网可达或当前 Pod 已授权。停止是正常可管理状态，不当成故障。

### 9.3 生命周期按实际宿主能力表达

| 动作/部署 | 界面行为与文案 |
|---|---|
| 关闭窗口 | 隐藏到仍存在的桌面宿主/托盘，不改变服务；平台没有后台窗口保留能力时不能假称仍在运行 |
| 独立代理已可用时退出 UI | “退出界面”，说明 Xpod 服务继续运行；不结束代理 |
| 当前 UI 进程仍拥有 runtime | 保留“隐藏窗口，后台继续运行”；真正退出用“退出并停止 Xpod”，提交前说明受影响应用/任务，不显示“退出后仍运行” |
| 服务由外部进程/服务管理器拥有 | “退出界面”，不杀外部服务；单独停止动作只有控制权和实际能力具备时可用 |
| 停止 Xpod | 明确停止的机器/服务及影响；停止结果按观测确认，不删除资料，不等于退出账号 |
| 产品级退出登录 | 复用 9/19 已定义的 logout coordinator；列明各 authority 的退出结果，只重试失败阶段；不创造组合 session |
| 单层退出 | 用“退出管理账号”“断开 WebID 会话”等明确名称；只调用对应 authority，不隐式退出另一层或停止机器 |
| 产品级切换账号 | 遵守 canonical X-1：先隔离并清理旧 WebID/Pod，再呈现新身份；不能将单层退出规则套用成保留旧身份绑定。退出失败时改点切号另见 §11 |
| 停止/退出后台代理 | 仅在实际支持时作为独立高级动作，说明失去远程启动能力；不能混入普通退出 UI |

服务页面尚未加载时，由桌面宿主渲染本地可用的启动/连接反馈，沿用 §6 展示时机，说明当前阶段及可用诊断。不得只让用户等待原生加载失败页；只调用已授权且实际存在的宿主启动/重试能力，不启动竞争实例。UI 展示时机不缩短既有服务恢复协议的超时，也不改变登录状态。

判断依据是可信的宿主能力/所有权，不凭版本号、进程名称或一个地址猜测。能力未知时保留安全的关窗/返回，不承诺后台存活；不得先退出再让用户发现服务消失。独立代理目标仍按 9/19 实施；本表仅让过渡版本说真话，不降低目标。

|---|---|---|
| shared-ui | 主题、Button/Input/Dialog 等 primitive、焦点/状态外观、无业务容器、通用 WebID 视图 | 私有颜色/焦点/弹层；将 Xpod Account 密码、注册、consent、创建业务下沉共享层 |
| extension-sdk/react | Rail/List/Content 布局协议、pane/stack、宿主能力和既有 authority 到视图的接线 | 固化不可覆盖的 Xpod 文案；生成第三个会话；因 provider 挂载启动无关恢复 |
| Xpod Shell/宿主 | 路由、窗口场景、菜单/托盘、能力反馈、生命周期文案 | 由表单决定窗口；凭未来代理架构伪造当前能力 |
| Xpod Account | CSS 表单、consent、Pod 管理、显式创建与安全续接 | 复制基础控件；用共享 WebID 登录视图接管 Account 业务 |
| 各工作区 | 本模块数据读取、任务、copy/i18n、权威状态映射 | 第二份模型/凭据/索引事实；越界修改公共规则 |

优先复用现有公开出口，先核对实际前端消费者再迁移/删除导出。不因文档指出重复就直接删除 LinX/extension 仍使用的组件。不新增依赖或通用状态库来完成本次设计收敛。

消费事实至少需要：准确对象标识、来源、观察时间或无时间原因、配置值与观测值、支持/不支持/未知能力、动作许可、当前任务关联。此清单是**UI 所需证据**，不是新后端字段/API 协议；已有适配器可提供就复用，缺失按 §11 处理，不能自行合成成功值。

## 11. 依赖与分期边界

| 能力 | 本轮设计已决定 | 实施依赖 / 缺失时呈现 |
|---|---|---|
| 公共主题、布局、文案、等待、路由 | 完整按本文实现 | 前端与宿主 owner 即可推进；缺后端运行证据不阻塞设计/fixture 验证 |
| 显式创建 Pod | 流程、结果和恢复按 §5 | Account controls、授权机器清单、健康检查、幂等任务查询、exact binding；缺哪步说明哪步，创建按钮不绕过它 |
| 产品退出与切号并发 | 正常协调退出、失败层重试、X-1 切号隔离沿用 canonical | 9/19 D-14 的新调用/重试/切号关系及 D-18 的放弃退出语义仍未定；认证 owner 先补领域规则。这些未定动作先不开放，不由 Shell/Account 各自设计；不得阻止已定义的失败层重试 |
| 绑定已有 Pod | 入口/失败展示已确定 | 控制权证明与首次关联协议尚待领域规范补齐；仅此能力暂不开放 |
| 独立宿主代理 | 目标与过渡文案已确定 | 9/19 的独立安装/控制通道/凭据/监督器；无证据时不宣称退出 UI 后仍运行 |
| 原生客户端配置 | 预览、确认、结果与恢复表达已确定 | 具体宿主适配器及回退能力；不支持时给真实手动方案 |
| 备份/迁移/导出、远程控制、P2P、索引重建 | 对象、影响、状态表达已确定 | 按现有领域能力逐项确认；不因设计列出主题就扩展服务端或展示成功 |

任务负责人先用前端能力声明和领域文档列出当前可接入范围；缺少能力证据记为“待接入/未核验”，UI 可制作明确标注的 fixture。真实发布前必须补对应实现版本与验证记录。后端协议缺口单独移交相应 owner，不要求全部前端工作停下，也不由本 spec 猜出协议。

W1 接口先定，随后 W2/W3 与工作区可以按边界并行；单一公共文件只分配一个写入 owner。每包先交实施范围与依赖清单，再提交小范围修改。本文未授权各路 AI 本轮自动运行或发布；用户派出具体实施任务时按该任务执行。

每包交付格式：实现范围/未覆盖范围 → 对应 D/AC 编号 → 变更文件 → 文档/前端/运行证据分层 → 未支持能力与 UI 表现 → 其他模块需接入的公共接口。复用[自查模板](../product-design-self-review-template.md)的 XP 原则，不再写第二套标准。

## 13. 验收合同

以下是**实施后**的验收要求。本次文档交付只验证规范之间的一致性、参数计算与链接，不把以下项目勾成已通过。

| ID | 必须证明的结果 | 适合的证据 |
|---|---|---|
| AC-01 | 所有工作区、Account、WebID 两主题使用同一 token/primitive；无私有主题或双重 focus | 前端引用检查 + 公共状态样例 |
| AC-02 | 实际组合小字≥4.5、必要边界≥3；选中/错误/禁用不只靠颜色；小尺寸 Logo 可辨，旧资产仍在 | 色值计算、视觉检查、资产清单；系统图标另验 |
| AC-03 | 键盘、Enter/Esc、错误焦点、200%文字与长内容完整；单一滚动不截断关键动作 | 前端行为/fixture；1440/1100/1024/768/640/390 宽，短认证另测280×400 |
| AC-04 | 五工作区/默认页/深链/历史单跳映射成立；断点切换不丢选择与草稿 | 路由及布局场景，包含未知地址和合法查询过滤 |
| AC-05 | Account-only、本机授权、WebID+Pod 三种任务各守 authority；失败隔离、切换不串对象 | 前端状态夹具；最终安全行为按领域真实验证，不用截图替代 |
| AC-06 | compact、Web Account、App Account 文档、工作区分别只有一个容器和窗口 owner；首帧主题正确 | 场景截图/窗口行为；普通与长错误分别覆盖 |
| AC-07 | 注册仅 Account；零 Pod 可达管理；明确创建后才提交；未知先重查原任务，读取失败不建 Pod | controller 行为用例 + 实施后的对应真实创建/恢复证据 |
| AC-08 | 无/多 Pod、缺 owner、错误 WebID、过期 interaction、切账号各有安全出口；未定绑定入口不可执行 | 状态/续接用例；领域校验实现另列版本 |
| AC-09 | 三服务、网络可达、机器在线、Pod访问互不冒充；用量未知非零；刷新保留有时间的可信快照 | 工作区失败/空态/刷新夹具及来源映射 |
| AC-10 | 保存、应用、检测、重启/重建分别反馈；取消等待不伪装撤销；危险动作对象和后果清楚 | 表单与操作状态用例，部分完成/响应丢失场景 |
| AC-11 | Provider 凭据、Xpod Key、客户端配置和模型角色不混用；Cloud目录/能力限制正确；跨模块能返回原任务 | AI 两模块共享场景，包含不支持/不可用/重建影响 |
| AC-12 | 托盘与 Status 一致；关闭/退出UI/停止服务/退出登录/代理退出按实际能力分开；产品切号遵守 X-1 | 宿主能力矩阵与平台验证；D-14/D-18 未定入口保持不可执行并单列后续验收；无证据不宣称后台完成 |

发布记录必须写清版本/提交、宿主与部署方式、验证场景和未完成依赖。fixture 只证明前端处理所给状态；一次真实成功也不能替代其他失败场景。历史文档的测试数量不自动继承为新版本通过。
