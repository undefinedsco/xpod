# Xpod 设计自查模板

依据：[DESIGN.md](../DESIGN.md)（产品设计入口）、[产品与体验纲领](product-design-charter.md)与[产品体验实施 spec](superpowers/specs/2026-09-27-xpod-product-experience-spec.md)，版本 2026-09-28 R6；同时依据[个人 AI 联合体验](../../homepage/docs/specs/personal-ai-product-experience-r6.md)，保留 R2 本机详细参数与 R5 目标审查。纲领判原则，spec 判具体参数、任务边界和验收；领域权威仍按二者列出的规范执行。

默认只读设计文档；必要时核对前端表达。不要为了填报告启动应用、登录、探查后端、运行完整测试或修改产品。若任务另外授权实施或运行验证，独立记录其范围与结论。

```text
审查通过不等于功能已实现或运行已验证；缺少运行证据不是本次设计审查
```

## 二、报告模板

以下为报告结构。删除未使用的说明文字；没有问题时也需要提供逐项判断的依据，不必为凑数制造问题。

### 范围与职责

- 模块 / 负责人：
- 审查日期 / 纲领与实施 spec 版本：
- 适用设计决定 D 编号 / 实施验收 AC 编号 / R5 PA01–PA07（本轮不冒充已做运行验收）：
- 用户任务（一句话）：
- 场景（桌面 / Web / 云端 / 本机 / 自托管，只列适用项）：
- 本模块负责 / 不负责：
- 前置模块 / 完成后去向：
- 审查层次：文档；或文档 + 前端表达。
- 已阅读的文件、章节或行号：
- 未覆盖范围：

### 适用依据

| 依据 ID | 文件与位置 | 适用对象 / 规则摘要 | 性质 |
|---|---|---|---|
| E-01 | `<实际路径#章节或行号>` | `<规则>` | 用户决定 / 领域规范 / 历史材料 / 前端表达 |

### 功能与操作是否成立（先于规则合规）

| 功能 / 入口 | 用户要作的决定 | 没有它哪条任务受损 | 保留 / 合并 / 降级 / 条件显示 / 删除入口 / 待证实 | 理由和受影响能力 |
|---|---|---|---|---|
| | | | | |

为1–3条主要任务列出：意图 → 用户必须决定的点 → 系统自行读取/校验的阶段 → 明确副作用 → 完成/部分失败恢复。区分文档推导与实测，不编造点击次数或使用频率。质疑既有规则时给出处、替代方案和权衡。

| 场景 | 首屏结论与关键事实 | 强调动作（允许没有） | 专业详情如何可达 | 当前页型及密度理由 |
|---|---|---|---|---|
| 正常 / 首次 / 停止 / 未知 / 异常（列适用项） | | | | |

判定含义：

- **符合**：本次审查层次所需的明确规则与材料一致；注明证据，不能据此声称功能已跑通。
- **偏离**：有明确适用规则，且阅读材料中有相反表达；列出两者。
- **缺证据**：本次层次缺少必要说明、状态设计或前端材料；写出缺什么，不假定结果。
- **待裁决**：适用规范仍冲突，或涉及尚未决定的共同规则；不是“实现麻烦”的替代说法。
- **不适用**：对象、宿主或职责不适用并说明理由；不能用来隐藏未设计的必要状态。

### 关键任务契约

| 项目 | 设计说明 / 前端表达位置 |
|---|---|
| 用户要完成什么，作用于哪个对象 | |
| 前置条件，由哪个模块负责 | |
| 主动作与改变范围 | |
| 提交、进行中、完成各说明什么 | |
| 等待、失败、部分完成时如何恢复 | |
| 取消、返回或离开会发生什么 | |

这些是体验检查维度，不是要求各模块新增一套相同的运行状态枚举。未涉及的状态标不适用；依赖现有 canonical 的直接引用。

### R6 逐对象、路径与证据检查

逐条走读设计中的对象与路径，不能只回答“有入口”“保留上下文”。至少为适用的知识来源、模型 release、Run 和空间资产各填一行；没有该对象则说明职责依据。

| 原任务 / 精确对象与版本 | 原入口 → Xpod 目标区域 → 返回 | 该区域所需 authority / 事实 owner | 保留的输入与已完成副作用 | 返回前重校验 | 设计证据 / 缺口 owner |
|---|---|---|---|---|---|
| 知识来源 / 模型 release / Run / 空间 | 给现有合法路径或业务位置；不得发明 API | Account、WebID/目标 Pod、本机控制分别列出 | 不含秘密或已失权内容 | 身份、权限、版本、范围、成本 | 文件 + 章节；协议未定明确挂起 |

逐项回答并指出页面位置：

1. 四入口是否只约束本机控制器？知识编辑、工作反馈、训练提交由谁承接？修复能否回同一资源而非通用首页？
2. Foundry 发布目标、runtime 可服务版本、客户端选择、Run 使用记录各来自谁、何时观察？缺观测时如何避免“已启用/已使用”误报？
3. 服务正常但原任务依赖失败时，影响在哪显示？可选未训练是否保持中性；当前任务确实受阻是否有恢复入口？
4. 产品切号是否执行 X-1 隔离？单层退出的标签与作用是否独立？训练授权是否被错误地从读权限推导？
5. 依赖修复、同一 Run 续接、训练重试分别改变什么？响应丢失如何查询原操作？取消请求、停止等待和已取消如何区分？
6. 停止/升级/退出分别影响哪些已知本机 Run、远端作业和未来调度？未知依赖如何表达，是否错误承诺自动恢复？
7. 导出、备份、迁移分别覆盖哪些资产字节、清单、来源、授权、外部 store 和凭据？恢复证据是什么？已发布模型是否被误当索引缓存？
8. 数据保存、推理/训练执行、产物存放与设备可达性是否分开？费用/配额/容量是否注明对象、周期、来源与时间，未知是否非零？
9. 知识来源精读和评估对照是否获得合适阅读区域，而非强用短认证窗或 28–32 px 诊断行？窄窗返回是否保留对象与焦点？

将回答关联到 R2 AC-15–AC-20 及联合 R6 的适用验收。前端 fixture 只证明所给状态的表达，不证明模型可运行、权重遗忘、训练取消或备份已恢复。没有协议的写 owner、待定输入和受阻动作，不能自行补协议。

### 问题记录

每个独立问题一条，共同根因只维护一条记录。

```text
问题 ID：<模块>-DESIGN-01
标题：<具体偏离及其用户影响>
判定：偏离 / 缺证据 / 待裁决
优先级：P1 / P2 / P3
关联原则：XP-xx
审查层次：文档 / 前端
适用规则：<依据 ID + 原文要点>
实际材料：<相反表达，或明确缺少的内容 + 文件位置>
用户影响：<影响谁完成什么，不猜测未验证的后端结果>
最小修正方向：<先修职责、文案、状态或归属，避免默认重构>
```

优先级服务于设计排期：P1 为核心职责、身份/授权/数据操作契约、任务闭环或错误承诺；P2 为影响理解、操作和公共一致性的局部问题；P3 为不改变主要任务的细节完善。按用户影响判断，可访问性问题也可能是 P1。不要将设计风险直接升级为已发生的安全漏洞或数据损失。

### 跨模块事项与交接

| 问题 ID | 主责 / 消费模块 | 可直接引用的决定，或待决定的问题 | 各模块需同步什么 | 完成条件 |
|---|---|---|---|---|

需要新决定时，写出相互冲突的依据、选项及用户影响。已有领域规范可以裁决的，直接列决定来源，不重复向用户确认。依赖未定事项的部分挂起，其余独立检查继续。

自查不自动授权修正。若另有实施授权：本模块可在分配范围内对齐已确定的规则；公共主题、组件和术语由共同责任方统一修正；一级导航、产品职责、身份与权限、自动化和数据操作语义不能由局部实现顺手更改。

### 结论

- 最重要的设计结论（不超过三项）：
- 值得保留的设计：
- 本模块可修正事项 / 公共层事项 / 待决定事项：
- 本次仍缺少的设计或前端材料：
- 本轮结论范围：仅设计审查；或设计与前端表达审查。

不得以“全部通过”省略范围。也不要因为没有启动产品，就把已经完成的文档审查写成无法开展。
