# Standalone AFS JS publication preparation

The source workspace stays private. The reviewed pure emitter creates a separate generic JS distribution. Platform module packaging is a different product; the generic launcher targets its own `dist/entry.mjs` and does not download or resolve a platform module.

`packages/xpod-afs/scripts/build-client-publication.ts` accepts the existing verified `--cli-package` and `--client-package` inputs plus one fresh `--output` under an existing canonical parent outside the source package. It calls the existing client builder, emitter, normal Bun pack and archive inventory checks inside one `withStagedProducerInput` callback. Ordinary client and platform builds are unchanged. It retains the normal tgz, byte/SHA256/SRI identity, producer material binding, inventory and closed command logs. The receipt does not grant source, consumer or release admission.

`scripts/check-afs-client-publication.cjs` takes one JSON request file with `publicationReceipt`, `publicationReceiptSHA256`, `registry`, `typescriptTool` (`path`, `sha256`) and a fresh `output` outside all package ancestors. The dependency registry must be explicit loopback. Missing exact normal dependency supply must fail; the consumer never rewrites archive dependency edges. This entry does not create registry metadata or an artifact catalog.

Each runtime gets an independent consumer directory and HOME. Bun installs the unchanged normal tgz, then Node or Bun runs the shared library behavior probe, every public JS export, and the local generic launcher-path check. Declaration checks use the explicitly hash-bound compiler. The exact installed package-local file/directory inventory, type, mode and bytes are compared to the original archive before imports; extra or linked members fail. The consumer result retains the checked archive bytes/SHA/SRI, original publication receipt bytes/SHA, and checked compiler path/bytes/SHA. Compiler authority remains caller-bound, not independent producer admission. Both installations use Bun; these are Node/Bun execution checks, not npm installation checks. The registry itself and its exact original dependency map require separate admission. `registrySemanticsQualified`, `sourceQualified` and `releaseQualified` remain false.

The library behavior probe is extracted unchanged from the existing manual-directory AFS checker into one helper. No phase/diagnostic policy changes are made to that checker. The publication command runner uses inherited pipes and waits for actual stdout/stderr EOF, leader wait, stream close and observed process-group absence before hashing complete originals. SIGTERM is followed by bounded SIGKILL and closure rechecks. Unknown inherited detached-pipe closure fails bounded and retains unhashed partial logs. Each stream has a fixed 8 MiB raw budget; overflow stops the command and records truncated/retained/observed bytes without a final original SHA. Truncated output cannot pass. Each stream also tracks write/short-write/pipe/flush/close/hash faults; observed bytes must equal retained bytes and all I/O must succeed before rawComplete can be true. Faulted streams retain io-incomplete-unhashed status and their original error codes without a final SHA. Hashing uses a bounded buffer after real closure; receipt-write failures preserve the original operation error. Exit/signal, EOF, group state and raw completeness are independent recorded facts. Windows cannot claim POSIX group closure and stays failed under this initial implementation. Successful consumer directories are removed; failed directories remain with the failure receipt for inspection. This does not attest arbitrary detached-daemon closure.

The initial verification uses tiny synthetic completed-build fixtures and actual normal Bun packing, plus failure/scope/hash controls. A genuine normal AFS build and public archive consumer have not been run as part of this patch. They require the coordinator's resource window, reviewed dependency originals and a new exact source-bound candidate; historical AFS and root compatibility failures remain unchanged.

Generated Components.js JSON-LD resource IRIs may include a fragment (for example, a compact dist/types/Journal.jsonld#Journal identifier). The emitter binds their local document path before the fragment, while retaining the original JSON-LD bytes. Missing or unsafe documents, unsupported payload types and symlink targets remain rejected.
