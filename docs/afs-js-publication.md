# Standalone AFS JS publication preparation

The source workspace stays private. The reviewed pure emitter creates a separate generic JS distribution. Platform module packaging is a different product; the generic launcher targets its own `dist/entry.mjs` and does not download or resolve a platform module.

`packages/xpod-afs/scripts/build-client-publication.ts` accepts the existing verified `--cli-package` and `--client-package` inputs plus one fresh `--output` under an existing canonical parent outside the source package. It calls the existing client builder, emitter, normal Bun pack and archive inventory checks inside one `withStagedProducerInput` callback. Ordinary client and platform builds are unchanged. It retains the normal tgz, byte/SHA256/SRI identity, producer material binding, inventory and closed command logs. The receipt does not grant source, consumer or release admission.

`scripts/check-afs-client-publication.cjs` takes one JSON request file with `publicationReceipt`, `publicationReceiptSHA256`, `registry`, `typescriptTool` (`path`, `sha256`) and a fresh `output` outside all package ancestors. The dependency registry must be explicit loopback. Missing exact normal dependency supply must fail; the consumer never rewrites archive dependency edges. This entry does not create registry metadata or an artifact catalog.

Each runtime gets an independent consumer directory and HOME. Bun installs the unchanged normal tgz, then Node or Bun runs the shared library behavior probe, every public JS export, and the local generic launcher-path check. Declaration checks use the explicitly hash-bound compiler. The exact installed package-local file/directory inventory, type, mode and bytes are compared to the original archive before imports; extra or linked members fail. The consumer result retains the checked archive bytes/SHA/SRI, original publication receipt bytes/SHA, and checked compiler path/bytes/SHA. Compiler authority remains caller-bound, not independent producer admission. Both installations use Bun; these are Node/Bun execution checks, not npm installation checks. The registry itself and its exact original dependency map require separate admission. `registrySemanticsQualified`, `sourceQualified` and `releaseQualified` remain false.

The library behavior probe is extracted unchanged from the existing manual-directory AFS checker into one helper. No phase/diagnostic policy changes are made to that checker. The publication command runner uses inherited pipes and waits for actual stdout/stderr EOF, leader wait, stream close and observed process-group absence before hashing complete originals. SIGTERM is followed by bounded SIGKILL and closure rechecks. Unknown inherited detached-pipe closure fails bounded and retains unhashed partial logs. Each stream has a fixed 8 MiB raw budget; overflow stops the command and records truncated/retained/observed bytes without a final original SHA. Truncated output cannot pass. Each stream also tracks write/short-write/pipe/flush/close/hash faults; observed bytes must equal retained bytes and all I/O must succeed before rawComplete can be true. Faulted streams retain io-incomplete-unhashed status and their original error codes without a final SHA. Hashing uses a bounded buffer after real closure; receipt-write failures preserve the original operation error. Exit/signal, EOF, group state and raw completeness are independent recorded facts. Windows cannot claim POSIX group closure and stays failed under this initial implementation. Successful consumer directories are removed; failed directories remain with the failure receipt for inspection. This does not attest arbitrary detached-daemon closure.

The initial verification uses tiny synthetic completed-build fixtures and actual normal Bun packing, plus failure/scope/hash controls. A genuine normal AFS build and public archive consumer have not been run as part of this patch. They require the coordinator's resource window, reviewed dependency originals and a new exact source-bound candidate; historical AFS and root compatibility failures remain unchanged.

Generated Components.js JSON-LD resource IRIs may include a fragment (for example, a compact dist/types/Journal.jsonld#Journal identifier). The emitter binds their local document path before the fragment, while retaining the original JSON-LD bytes. Missing or unsafe documents, unsupported payload types and symlink targets remain rejected.

The notice tree preserves conventional extensionless LICENSE, LICENCE, NOTICE and COPYING documents (case insensitive), alongside the existing JSON/TXT/MD notice formats. The JavaScript collector copies the repository LICENSE to dist/licenses/LICENSE; staging retains those exact bytes and inventory hashes. This classification applies only within dist/licenses, keeps unknown names/extensions, executable notice files, symlinks and native payloads rejected, and grants no legal or release admission. Notice object existence and hash checks still apply.

The separate `AFS JS normal archive consumer` workflow checks out the immutable Actions SHA on Linux and macOS, installs locked build tooling and runs `scripts/check-afs-js-archive-ci.cjs` with a fresh canonical directory under RUNNER_TEMP. The orchestration uses the existing normal CLI producer, verifies its copied source inputs against the full tracked Git snapshot, extracts the exact normal CLI/client archives with the existing archive parser, and runs the original normal AFS builder. AFS and its same-checkout client are supplied through the generic exact registry with real npm PUT operations using the existing publisher. Reserved local identities cannot fall back to public packages; public recursive dependencies use the unchanged Bun resolver and npmjs upstream. This is an online consumer check, not an offline closure or frozen transitive dependency catalog.

The original archive consumer remains responsible for both Bun installations, the shared library behavior probe, all public ESM/CJS exports, local generic launcher and NodeNext declarations. No platform launch is added. The workflow always uploads normal archives, publication/consumer receipts, original npm metadata, full before/after source snapshots and closed raw command receipts. Before/after source identity and content must agree and remain clean; failed or missing commands, archive hashes, local supplies and source bindings fail the job. The orchestration retains source/legal/native/release admission as false and records loopback fixture publication separately from public release. Its local contract tests do not constitute an actual CI or archive-consumer pass.

Registry teardown observes the existing server and its sockets before listen. It allows 250 ms for natural closure, then attempts connection reclamation and observes for up to another 1000 ms. Receipts distinguish natural-closed, forced-closed and unknown from the actual server close event plus socket close observations; elapsed budget is never evidence of closure. Forced or unknown closure fails the run. Teardown, source-after verification and final receipt writing are attempted independently. Structured error chains preserve the original operation failure alongside closure, source verification or receipt-writing errors; a receipt-writing failure also propagates on stderr. This budget governs fixture teardown only and changes no producer, install, probe or declaration timeout.

The normal CLI entry has its own stricter evidence layout: its fresh evidence directory must be below the checkout's ignored `.test-data`. The CI driver uses `.test-data/afs-js-archive-ci-producer` for those original CLI/client archives and receipts, while AFS stages and consumers stay under the external RUNNER_TEMP directory required by their contract. The driver records the CLI evidence coordinate without moving or copying originals, and an independent always-upload step preserves that directory as `afs-js-cli-producer-<OS>-<checkout SHA>-<run>-<attempt>`, alongside the external AFS/consumer artifact. Hidden-file inclusion is enabled only for that exact owned CLI producer directory, never the wider repository or `.test-data` tree. Missing CLI evidence before producer startup is reported as an upload warning; the failed producer phase still fails the job. Existing evidence remains a hard failure, never an input to a new run.

AFS value-export discovery and declaration emission share one fresh TypeScript Program, compiler host and checker from `tsconfig.build.json`, bound to the caller's live normal CLI/client SDK inputs. Export discovery no longer creates a separate broad program that includes build scripts and tests. Each fresh client or module producer still creates its own Program; no Program survives a producer scope. All configuration, pre-emit and emit diagnostics remain enforced, and live input assertions run before and after declaration emission. Public type targets come from those packages' exact manifest exports and use the same confined export-path resolver as runtime producer imports. Exact subpaths with explicit `.d.ts`, `.d.mts` or `.d.cts` targets are supported; undeclared SDK subpaths, missing declarations, unsafe paths and symlinks fail without consulting a workspace SDK. JSON data exports are excluded from the type surface. No second package/subpath declaration table is maintained.

The builder validates existing producer materials before compilation, retains the existing staged producer lifetime, and hashes selected manifests and all SDK declaration files read by the compiler. It checks those inputs before and after real TypeScript declaration emission, declaration rewriting and the remaining metadata/notice collection. Configured compiler options and strict diagnostics stay in force; the existing skipLibCheck setting is unchanged. Declarations retain public package specifiers, not temporary SDK filesystem bindings. This fixes fresh-checkout declaration input resolution; it does not grant normal build, consumer or release acceptance until those gates execute on the new source.

SDK confinement also applies to transitive declarations: compiler file probes, reads, realpath resolution and SDK-relative import/reference targets use the same artifact path capability as public exports. Initial reads and later hash assertions recheck every ancestor for symlinks and verify the physical root, so same-byte symlink substitutions cannot pass. SDK-relative and triple-slash path references cannot escape their own SDK root. Bare public dependency specifiers continue through the original TypeScript resolver; they are not treated as owned SDK-relative paths.

Known SDK `reference types` directives use the same manifest-derived bindings as imports and reject undeclared SDK subpaths; they never fall back to another installed copy of that SDK. Bare external public type directives retain the standard TypeScript resolver. SDK compiler text is decoded from the single raw Buffer whose SHA is recorded, then current disk bytes are independently checked afterward. UTF-8 BOM, UTF-16LE BOM and UTF-16BE BOM follow TypeScript's Node `sys.readFile` decoding, including preservation of raw input bytes; a second read is never used to claim which bytes the compiler consumed.

For public type-reference dependencies the wrapper forwards the reference's explicit resolution mode, falling back to the containing file's inferred mode, to the original TypeScript resolver. Conditional import/require type exports therefore retain standard Bundler and NodeNext ESM/CommonJS selection.
The mode-aware CompilerHost hook is used because TypeScript's legacy hook receives directive names after explicit per-reference mode metadata has already been discarded; TypeScript's own getModeForFileReference selects the original mode without a separate condition table.

Ordinary module imports likewise use the official mode-aware module-literal hook and TypeScript's getModeForUsageLocation. Public resolution receives the original literal, containing source file, compiler options and project reference, preserving per-import attributes and inferred ESM/CommonJS mode. Known SDK imports still use the same explicit manifest binding and confined path/Buffer guards.
