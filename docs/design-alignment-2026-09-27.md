## 3. R1补全的实施决定（历史）

以下记录R1当时补全的细则，**不是用户此前逐项选定，也不是已经上线**。五底Tab、固定首屏与十二项验收等已由§6记录的R2替代：

- §3：各主题目标 URL、明确旧路由映射、兼容保留期限、查询参数与返回目标边界。
- §5/§8：工作区与 Account 文档窗口默认值、尺寸口径、窄屏五项导航、断点和滚动规则；保留 280×400 短认证基线。
- §6：300ms 阶段反馈、10s 延长等待说明，均不改变认证状态或重复事务。
- §8：深色主题、非色彩语义状态、控件密度、公共浮层和焦点；静态对比度依据。
- §9：选定 Logo 到平台资产的映射、托盘状态表达、过渡期退出文案。
- §11–§13：能力缺口处理、七个工作包和十二项验收合同。

深色未复用固定墨紫作为小字与焦点，因为其与暗画布的对比度约 1.93:1；浅色 control 在 tint 上约 2.99:1，改用已存在的强边界角色。这是具体组合修正，不是给每个模块另添一套颜色。

## 4. 仍需实施阶段证明的边界

1. 绑定已有 Pod 的控制权证明与首次关联协议仍在 9/19 规范中待定；仅该功能保持不可用，不接受 URL 就宣告成功。
2. 显式创建涉及授权机器清单、服务健康、幂等任务恢复、exact binding；前端拆分记录不能证明这些后端依赖已发布。
3. 独立代理、原生客户端配置、迁移/导出、P2P、重建等在真实产品中按实际部署能力接入；目标稿按§7允许完整展示已确定设计及示例状态，不因当前未实现一律禁用。
4. 产品退出失败后改点切号、新退出调用与重试的关系、放弃退出语义仍由认证 canonical 的 D-14/D-18 跟踪。只暂缓这些未定动作，正常退出与失败层重试继续按既定契约实施。
5. 平台图标打包、真实主题首帧和实际交互须由实施阶段验证；本轮色值计算与文档审查不能替代它们。

| 对象 | R2改变 |

| 根DESIGN、纲领、模板 | 去掉旧结构不可变假设；新增逐功能取舍、完整用户决定链、首屏预算和行为气质检查；不再只验token和文档一致性 |

导航合并不合并会话、凭据或数据owner。模型默认等产品行为涉及运行侧适配，已列§11依赖；文档纠错不能冒充代码完成。删除源资料后的派生结果清理是来源/权限一致性规则，不作为普通设置开关。

这些是有文档依据的设计裁决，尚未做真实界面可用性验证。后续实施应验证任务是否更连续、信息是否足够，而不是仅证明四个菜单或新颜色出现。

R2核查结果（2026-09-27）：本轮11份文档、104个本地Markdown链接核查通过；范围内diff空白、Markdown表格/围栏、D-01至D-10、W1至W7、AC-01至AC-14及UX-01至UX-10编号检查通过。独立交叉复核发现的聚合页权限门禁、AI深链归属、旧跨页流程、密钥行密度、派生清理开关与全量托盘菜单已直接修正；参数复核未见主spec与Shell的尺寸/密度冲突。上述结果只证明本轮文档检查，不证明真实界面的可用性、产品能力或发布状态。
