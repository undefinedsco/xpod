# Xpod 桌面外壳与共用 applet 产品设计

日期：2026-10-01。状态：设计已与产品负责人逐项确认，**未实现**。

范围：Xpod 桌面端除登录以外的全部模块，包括外壳（rail、个人卡片、通知中心、收件箱、托盘、窄窗）、这台设备、AI 连接、Pod、任务与待办。登录前门和账号页由[登录前门设计](2026-09-29-shared-ui-pod-sign-in-design.md)负责，不在本稿范围。本稿只在需要交接的地方引用它（见 §11）。

画板：https://claude.ai/artifact/5935iJ5q9fds4esW61jaAo 。源文件归档在 [`assets/2026-10-01-xpod-desktop-shell/`](assets/2026-10-01-xpod-desktop-shell/)，本地渲染方法见该目录的 README。

依据：[审查交接](../handoffs/2026-09-30-product-review-handoff.md)。与 [R2 本机体验](2026-09-27-xpod-product-experience-spec.md)、homepage R6 冲突的地方列在 §9。本稿以现有代码为事实依据：画板上每个字段都对照过代码，没有接口的一律标「待接入」，并汇总在 §10。

## 1. 已定的总原则

| 编号 | 决定 | 一句话 |
|---|---|---|
| S-01 | **两个宿主，共用 applet** | LinX 和 Xpod 桌面都是宿主。任务、AI 连接、Pod 这些 applet 在两个宿主里用同一个 body，宿主只负责 rail。宿主之间的能力差异，按 extension-sdk 的宿主能力声明降级处理（例如没有 `aiClientConfiguration` 能力时，只提供"复制配置"）。LinX 不是 Xpod rail 上的一个入口。 |
| S-02 | **配置跟壳，数据跟 applet** | 壳只管平台级配置（AI、检索、授权、网络、设备）。数据的查看和编辑交给 applet。判断依据是"在哪改"，不是"存在哪"：比如 AI 配置存在 Pod 里，但在壳里改。 |
| S-03 | **两层身份** | applet 需要 WebID 登录。"这台设备"和"设置"用本机宿主权限，没登录也能打开。Account 只出现在账号服务自己的页面里，入口是个人卡片上的"管理账号 ↗"。壳本身不持有 Account 会话。 |
| S-04 | **三栏版式** | rail 宽 64，只放图标；上面是你和 applet，下面是宿主自己的入口。列表栏宽 260 至 280，头部 48 高，放搜索框，能新增时再加一个 ＋。内容栏头部也是 48 高，左边是标题，右上角依次是同步状态、通知、收件箱。每屏只有一个标题。 |
| S-05 | **最小配置** | 用户填不了的细节（解析时机、回退顺序、检索引擎等）用内置默认值，只在开发者模式里显示。可选范围靠下拉框的选项来限制，不写解释段落。缺资源时给"领免费额度"入口，不让用户去配置。 |
| S-06 | **模型在哪里起作用，就在哪里选** | 同一个选择只有一个编辑入口；要反查某个模型被用在哪里，看"用于 …"标注。 |
| S-07 | **出错只留一行** | 沿用登录审查的规则：一行写原因，配一个能直接解决问题的按钮；技术细节（如 HTTP 状态码）只在开发者模式里显示。 |
| S-08 | **用户可见的用语** | 只用 WebID、Pod、Xpod 云端、Xpod 边缘、设备、网络、连接、Xpod 密钥、任务、待办。不出现 route、binding、issuer、provider、Gateway、CSS 这类实现词。完整用语表见 §8。 |

视觉沿用 `packages/shared-ui/src/theme.css`：
- 纸色 `#F7F4ED`、墨紫 `#563E84`；
- 系统字体；正文 14px，最小 12px；
- 精确指针下控件高 36px，主按钮 44px；
- logo 和头像一律用圆角方形。

## 2. 外壳（画板 S 组）

### 2.1 rail
- **Xpod 桌面**：从上到下依次是头像、任务、AI 连接、Pod；底部是这台设备、设置。
- **LinX**：头像下面是 LinX 自己的入口（由 LinX 决定），再下面是共用的任务、AI 连接、Pod，底部是设置。
- 只放图标，名称写在 `title` 和 `aria-label` 里。
- 这台设备需要处理时，图标上出现一个点。

### 2.2 个人卡片（S2，参照微信）
点头像弹出，内容依次是：
- 大头像、名字、WebID（可复制）、地区、签名；
- 一行 Pod 信息：存放位置和就绪状态，点这一行进入 Pod；
- 管理账号 ↗、切换 WebID、退出。

### 2.3 未登录（S1）
- 头像位置换成"登录"。
- 内容区显示登录前门的 A1。
- 这台设备和设置照常可以打开。

### 2.4 通知中心（S3）
分上下两区：
- **需要你处理**：表示一种状态，处理完才会消失。它和托盘用的是同一份数据，汇总所有 applet 的待处理事项：
  - 访问申请（Approval）；
  - 运行在等你确认、运行失败；
  - 设备网络出问题；
  - 空间或流量快到上限：超过阈值（例如 80%）才出现，平时不显示。
- **动态**：表示事件，看过就过，比如"AI 新建了任务""索引重建完成"。"全部已读"只作用于这一区。

每一条都只是一个指针，点了跳回对象所在的地方去处理，任意一处处理掉，所有入口同时消失。

### 2.5 收件箱（S4）
- 就是 Pod 的 Solid Inbox（`InboxNotification`）：别人发来的东西，比如访问申请、分享、回复。
- 访问申请的消息上直接放"允许读取 / 拒绝"。它对应的是一个 Approval 对象，所以同时也出现在"需要你处理"里。

### 2.6 托盘（T 组）
从上到下：
1. 最上面是你：名字加 WebID，右边有复制图标，点这一行就复制。
2. 状态只写两三个字：运行中 / 仅本机可用 / 已停止。
3. **需要你处理**：只列前 3 条，每条都能跳回原处处理；访问请求用子菜单直接允许或拒绝。后面跟"全部查看 ›"。
4. **进行中**：只在有长任务时出现。
5. 打开 Xpod。
6. 底部：停止或启动、更新、关于、退出。开机启动不放在托盘里。

**退出要先确认**：现有代码在退出时会一起停掉这台设备上的 Xpod，所以确认框要写明这一点。

### 2.7 窄窗（390 宽）
- 只保留内容栏，顶部是"上级 › 当前页"。
- 左上角打开抽屉，抽屉里是"rail + 列表栏"。

## 3. 这台设备（D 组）

列表：网络访问 / 服务状态 / 运行设置 / 查看日志。状态写在每一行的右侧，不在列表顶部放大卡片。

### 3.1 网络访问（和账号页的设备行共用同一个 body）
- 三项检测：这台电脑、局域网、其他网络。
- **隧道可以多条同时生效**：
  - 每条隧道一行：名称、地址、状态（可访问 / 失败（原因）/ 已停用）、启用开关；其中一条标"主地址"。
  - "其他网络"一项按汇总显示，比如"1 / 2 条隧道可用 · 仍可访问"。
  - 只坏了一条时发一条轻提醒；全部不通时，才发"其他设备访问不到"。
- 隧道服务商和每家要填的字段，由 `TunnelProviderCatalog` 的声明生成，不按服务商写分支：
  - `endpointSource=declared` 时多一个"公网地址"字段；
  - `originOwner=console` 时显示"把隧道指向 127.0.0.1:…"这一步；
  - `runtimeSupported=false` 的服务商置灰。

### 3.2 服务状态
- **核心服务**：入口网关、Solid 服务、API 服务、查询引擎（QLever）、任务调度（Inngest）。
- **可选组件**：cloudflared、ngrok、frpc，状态分"运行中 / 未使用 / 未安装"，未安装的给"安装方法 ↗"。
- 页面上方是"重启 Xpod / 停止 Xpod"；Xpod 停止时，主按钮换成"启动 Xpod"。
- 写明"停止只影响这台设备"。

### 3.3 运行设置
- 开机时启动 Xpod；
- 意外退出时自动重启（你手动停止的不会被重启）；
- 数据位置：可在访达中显示，也可以更改；
- 运行方式：只读；
- 端口、访问地址等进开发者模式。

### 3.4 查看日志
四个筛选：来源、级别、时间、搜索。

## 4. AI 连接（A 组）

列表：**Xpod（下游）** 加各家服务商（上游）。这一结构沿用现有的 `packages/ai-connections`。

### 4.1 服务商详情（上游）
- **当前连接**：
  - 授权方式按服务商实际支持的列出，例如浏览器登录、设备码登录、已有登录态、添加 API Key。
  - 多条凭据组成凭据池，可以拖动排序；每行写明接入方式和账号，比如"ChatGPT 订阅 · xiaolin@…"、"API Platform · sk-…"。
  - 每条凭据显示额度（5 小时、本周、可用余额），控制台和账单链接放进这一行的"⋯"菜单。
- 不再有单独的"接入信息"一节；接口地址只在开发者模式里显示。
- **模型**：
  - 按 `@undefineds.co/models` 的 `AI_MODEL_CLASS` 分标签页：对话、向量、文档理解、重排、语音合成、语音识别、图像生成、视频生成，再加决策（待接入）。只显示这家服务商实际有模型的类型。
  - 能力（推理、视觉识别、函数调用、文档输入、联网搜索）用图标表示。
  - 向量模型另外显示维数。
  - 已加入的模型标出"用于 …"。
- **凭据异常（A7）**：每条凭据只写一行原因，配一个解决按钮。状态码分类按 `ProviderRuntimeAdapter`，冷却和切换按 `AiGatewayService`。

  | 错误 | 用户看到的 | 按钮 |
  |---|---|---|
  | 401 | 密钥无效或已被撤销，已跳过 | 换一把 Key |
  | 登录刷新失败 | 登录已过期 | 重新登录 |
  | 402 / insufficient_quota | 额度用完了 | 去充值 ↗ |
  | 429 | 请求太频繁，几点后自动恢复；网关先换用下一条凭据 | 无 |
  | 403 | 没有这个模型或地区的权限 | 查看原因 |

  凭据池上方用一行汇总，比如"6 条里只有 1 条能用"。整家服务商不可用（5xx、网络或代理问题）时，同样在凭据池上方放一行提示。

### 4.2 Xpod（下游）
- **Xpod 密钥就是 CSS 的 Solid 客户端凭据**：发给客户端时包成 `sk-base64(id:secret)`，见 `ClientCredentialsAuthenticator`。它的权限范围是**整个 WebID**，每一行都写明"范围：整个 Pod"。只限 AI 的密钥属于后续需求。旧式的 Gateway Key 退场。
- **密钥列表只有一份，就放在这里**。登录模块账号页的"密钥"分区只放一个入口链接（见 §11）。
- 没有单独的客户端列表。每把密钥上写明应用到哪里，对应 `appliedTo`、`appliedOn`、`appliedAt` 字段。
- **新建分两步**：
  - **A4**：只填名称，加一个下拉选"给哪个客户端用"。下拉的选项来自宿主声明的 `AiClientId`（codex、claude-code、pi、codebuddy）并带安装状态，再加一项"不写入，只复制"。不问模型：客户端默认跟随 Pod 的"智能"模型。
  - **A5**：显示地址和密钥，各带复制按钮，写明密钥只显示这一次。选了客户端的，主按钮是"写入 {客户端}"，写入前备份原文件。宿主没有写入能力时，只能复制。
- **密钥异常（A6）**：

  | 来源状态 | 用户看到的 | 按钮 |
  |---|---|---|
  | `drifted` | 配置被改动过 | 重新写入 |
  | `failedAndRestored` | 写入失败，原配置已恢复 | 重试 |
  | `unverifiable` | 已写入，还没验证 | 测试一次 |
  | `unavailable` | 这台电脑上找不到这个客户端 | 改为只复制 |
  | 上游额度用完 | 调用失败：某服务商额度用完了 | 去那家服务商 |
  | 已停用 | 已停用，有调用被拒绝 | 启用 |
  | 只存了 hash | 密钥原文没有保存，不能再显示 | 重新签发 |

  遇到 `service_access_missing` 时，所有密钥都会失效，所以只在整组上方放一行提示，主按钮是"允许 Xpod 访问"。

## 5. Pod（P 组）

列表：模型设置 / 检索与索引 / 授权应用 / 数据管理。

### 5.1 模型设置
- 一张默认模型清单，按模型类型分组，分组名和 AI 连接的标签页一致。"应用没有指定模型时用这里的默认值，随时可以改。"
- 每一行右侧放"测试"（就是现有的就绪测试）或"待接入"。

| 分组 | 默认项 | 默认值 | 代码现状 |
|---|---|---|---|
| 对话 | 智能、快速 | Xpod 提供 | 现在只有一个 `chatModel`，拆成智能、快速两项属于待接入 |
| 对话 | 视觉辅助（只列有视觉能力的模型） | 不使用 | 对应现有的 `ocrModel` |
| 文档理解 | 文档理解 | PaddleOCR · 百度（Xpod 提供） | 对应 `readerModel`；默认首选 `paddleocr`，见 `ReaderAiConfig` |
| 向量 | 语义检索 | 只读显示，右侧"去更换 ›" | 只在检索与索引里改 |
| 语音 | 语音合成、语音识别 | 不使用，平台不提供 | 待接入 |
| 图像与视频 | 图像生成、视频生成 | 不使用 | 待接入 |
| 决策 | 决策（类 JEPA） | 不使用 | models 里还没有这个类型，待接入 |

- 重排、索引摘要不开放给用户。
- 文档解析的其他选项（处理时机、OCR 各开关、回退顺序、失败处理、上限）全部用内置默认值，只在开发者模式里显示。
- 某一项没有可用模型时，那一行给"领免费额度 ›"入口，依赖 §10 的目录字段。

### 5.2 检索与索引
- 全文检索、语义检索、渐进式索引三个开关。语义检索的说明写明"资料片段会发给向量模型的服务商"，这是外发前必须告知的。
- **语义检索用的 Embedding**：显示当前模型，旁边一个"更换"按钮。
  - 更换时（P3）先选来源：Xpod 提供 / 用我自己的 Key（BYOK）。
  - 云端 Pod 的下拉里只列目录内的模型，边缘设备列出全部，这样不需要写解释。
  - 写明后果：更换后会重建全部语义索引，重建期间只能全文检索。主按钮是"更换并重建索引"。
- **索引**：
  - 显示待处理数量和配置版本；
  - 列出最近几次重建任务的状态和进度；
  - 可以分项重建：全部 / 只重建全文 / 只重建向量；
  - 三个维护开关。

  这些都只用现有的 `AiConfigLifecycleSnapshot` 数据，不显示整体进度或阶段文字。

### 5.3 授权应用
- 每个应用一行，"⋯"菜单里有修改权限、撤销。点开一行，看这个应用的流量和访问记录（按应用计量待接入）。
- Xpod 后台访问也在这里。它没有授权时，主按钮直接是"允许"（P6 刚创建的 Pod 就是这种状态）。
- 以后这一页要扩成"授权"页，见 §7。

### 5.4 数据管理
- **用量**：存储、流量、AI 用量、计算时长，用现有 `pod-settings` 接口的数据，数值用占位。
- **导入、导出、迁移**：都标待接入。迁移入口跳到账号页去做；现有的 `PodMigrationService` 只是在云端集群节点之间改路由，不是在设备之间搬数据。

## 6. 任务与待办（K 组）

**模型**：用 models 里同一个 `Task`，交给谁看 `assignedTo`。
- 交给代理的，就是带 Schedule（cron / interval / event）和运行记录（Run / RunStep）的 AI 任务；
- 交给你自己的，就是待办。

界面只读 Pod 里的数据，不读 Inngest。

- **列表**：
  - 顶部筛选：全部 / 我的 / AI 的；可以在清单和日程之间切换。
  - 分组规则，保证列表不会被撑爆：
    - **在等你**：始终展开；
    - **我的待办**：第一行是"＋ 添加待办，回车"，按截止日期排序，只显示 5 条，下面一行"还有 N 条"；
    - **AI 按计划在做**：默认收起，只显示数量；
    - **已结束 · 最近 7 天**：默认收起，更早的从"查看全部已完成"进入。
  - 待办左边是勾选框，AI 任务左边是类型图标（日历 = 定时，循环箭头 = 周期，闪电 = 事件）。
- **任务详情（K1）**：要做什么、什么时候（带类型标签）、下次运行、能动哪些资料、怎么来的（AI 建的任务链回当时的对话）、最近运行。
  - "立即运行一次""暂停后续运行"和运行详情里的"停止这次运行"是三件事，分开放。
  - 不显示是哪个代理在执行。代码里任务带 `runner` 字段（默认 `pi:pi`），执行身份用的是那个代理自己的 Xpod 密钥，属于代理级；这些只在开发者模式和密钥列表里能看到。
- **运行（K2、K3）**：
  - 停下来等你确认时，就在运行详情里决定，确认后**同一次运行**接着做（对应 `waiting_input`）。
  - 失败时写明哪一步失败、前面做完了什么、有没有副作用，主按钮去修复对应的连接；修好后从失败的步骤继续，不从头重跑。"从这一步继续"属于待接入。
- **新建（K5）**：只填"要做什么"，再选"什么时候"：定时、周期、事件三选一，下面换成对应的填法。不提供"一次"：现在就要做的事在对话里交给 AI，以后要做的记成待办。
- **AI 可以自己建任务**：建好后发一条"动态"通知，任务详情里写明怎么来的。列表上不另外标"AI 建"。
- **我的待办（K7）**：标记完成、截止日期、重要程度、怎么来的、备注，并可以"交给 AI 去做"。
- **日程（K8）**：按今天 / 明天 / 本周分组，放有截止日期的待办、定时任务的下一次运行，以及在等你的事。周期和事件任务不放进日程。

## 7. 消息、审批、授权的分层（已定，画板待画）

| models 对象 | 含义 | 唯一的家 | 其他入口 |
|---|---|---|---|
| `InboxNotification` | 收到的东西（actor → object） | 收件箱 | — |
| `Approval` | 一次决定：这一次允许吗（带 risk、toolName、expiresAt） | 它的来源处：运行详情、收件箱里的那条消息 | 需要你处理、托盘、任务里的在等你 |
| `Grant` | 长期授权：以后都允许（带 effect、riskCeiling、revokedAt） | **授权**页：应用、AI、别人三类，加上我发出的申请 | — |

规则：
- 批准一条 Approval，默认只对这一次有效。只有用户明确勾选"以后都允许"时，才生成 Grant。
- AI 请求批准的卡片在所有入口用同一个组件，内容包括：要做什么、风险高低、多久过期，选项是"只这一次 / 以后都允许 / 拒绝"。

## 9. 与现有 spec 的偏差（都已由产品负责人确认方向）

1. **R2 D-01 的四个入口**（概览 / 存储空间 / AI / 服务与访问）改为：rail 上放任务、AI 连接、Pod，底部放这台设备、设置。"概览"入口删除；状态改由各页的一行结论和托盘表达。"存储空间"这个名词停用，改叫 Pod。
2. **R2 §7.2**：Pod 的清单和新建只在账号页做。现有 `/settings/pod` 里的"创建存储空间"表单删除。
3. **R2 §3.1**：AI Config 里的 search-indexing、index-lifecycle 原本划给"存储空间"，现在合并到 Pod › 检索与索引；model-assignments 改为 Pod › 模型设置。
4. **AI Connections 规范**：去掉单独的客户端列表，客户端改为密钥上的属性；provider 目录保持常驻（沿用现有设计，不采纳 R2 "只在添加时出现"的规定）。
5. **R6 XC/XK**：知识页暂不做；任务做成数据 applet，日常编辑不只交给 LinX。这是因为 applet 两个宿主通用，LinX 的"工作"可以直接嵌这个 applet。

## 13. 现状问题（2026-09-30 在隔离的 Standalone 上实测）

实测方法：起一个隔离的 Standalone，`SOLID_OIDC_ISSUER` 设成它自己的 baseUrl，并用隔离的 `XPOD_LOCAL_SETUP_PATH`，不连真实 Cloud。

1. **导航**：现在是五个只有图标的入口（AI Connections / AI Config / Network / Status / Settings），R2 的四入口没有落地。Status 下面有 13 项技术目录。390 宽时只剩二级导航，看不到内容。
2. **用语**：中英文混排，满屏实现词，例如 Canonical URL、nodeId、"DDNS is not enabled (missing XPOD_NODE_TOKEN)"。
3. **身份**：Settings 里的 ACCOUNT 分组放的其实是 WebID 和 Pod；"Current account"显示成 `card`；Pod 页同一页里既写"Not discovered"，又列出了已有的 Pod。
4. **出错**：新建 Pod 后，AI Config 只显示一张泛泛的"could not be loaded"卡片，实际原因是 `service_access_missing`，本该给出"允许 Xpod 访问"。
5. **事实错误**（根因未查）：概览里"本机"一项显示 `127.0.0.1:3000`，实际端口是 40555；`localhost` 被当成"公网"；运行方式显示 unknown。
