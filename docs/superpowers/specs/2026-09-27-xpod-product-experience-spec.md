## 2. 产品任务、信息层级与文案

Xpod 的完整产品目标包含数据主权、个人知识、任务与个人模型资产。本文 R2 主要规定资料保存、应用连接和本机运行控制面；桌面端保留服务、网络、AI 接入和配置。LinX 承担日常协作、示范与纠正体验，新增目标按§16交接。Xpod 沿用现有保存与控制能力；存储空间入口是已有 Pod 管理的产品组织，不借此新增文件浏览器或复制 LinX 的聊天业务。

北极星“个人日志合并在一起，就是整个文明的历史”指导长期取舍；工作区先解决今天的操作。界面不以永久保存、全天在线、默认本地推理、永不外发或代替用户做主作为未经证实的承诺。

内容按页型组织：概览先结论/影响，配置先作用对象/当前结果，集合先对象，诊断先范围/证据。正常页面不强求一个大号主按钮；只有真实需要推进的当前任务才强调主动作。一个区域可有次要动作，保存、测试、删除不能同等强调。正常不制造警告，专业诊断仍可直达。

本机控制器顶层中文使用“概览 / 存储空间 / AI / 服务与访问”，英文使用“Overview / Storage Spaces / AI / Services & Access”。AI Connections、AI Config 继续是业务责任域，不再强制成为两个一级入口。Account 首次说明为“管理账号”，WebID 首次说明为“WebID 身份”，Pod 首次说明为“Pod 存储空间”，后续保留准确名称。产品文案由应用的现有国际化层提供；不新增 SDK 硬编码文案。

原始资料、派生索引、提供方凭据、Xpod API Key、机器凭据分别命名；不用“数据”“连接”“退出”包办不同对象。身份、Pod、机器切换后的标题与动作范围必须同步，旧请求不能覆盖新对象。

## 3. Shell、导航与 URL

### 3.1 以任务组织的单一导航

本机控制器用有文字标签的“概览、存储空间、AI、服务与访问”，身份入口另列。Account/WebID/Pod 仍有各自权威，没有把它们合成一个全局账号或作用范围。页面标题明确当前机器/实例、空间或连接；不能用一个全局选择器暗中切换所有对象。

| 入口 | 首要任务与页面组织 | 基础路径及子目标 |
|---|---|---|
| 概览 | 判断当前可用范围与需处理事项；直接内容页，不附18项目录 | /status/overview |
| 存储空间 | Pod清单、空间资产、位置、用量、权限、搜索覆盖和备份；复用现有管理body | /settings/pod 保留为入口；页内section=overview/access/usage/search作为非敏感展示选择，身份与Pod选择仍由权威校验 |
| AI | 连接客户端、为资料处理或已发布个人模型选择用途，核对运行版本 | /ai-connections；section=clients/connections/keys作为展示选择；用途深链逐条按下表归属 |
| 服务与访问 | 服务与启动、访问与连接、对外访问、诊断；同一任务内看状态、修改、确认结果 | /settings/runtime、/status/logs及下列专业深链为现有路径；/network/overview、/network/domain-dns为本轮目标路径，现有 /dashboard/network、/settings/network 按 §3.3 迁移；默认 /settings/runtime |

展示section是**本次前端路由目标**，不是新API或授权证明；仅接受已列枚举。已有业务路由参数由对应owner迁移，不覆盖OIDC或CSS事务。若宿主不支持机器管理，只呈现真实可用的访问内容与原因，不暗示云端用户拥有主机控制权。

| AI Config 既有深链 | 固定导航归属 | 任务上下文 |
|---|---|---|
| /ai-config/model-assignments | AI | 用途模型详情；保留经验证的目标Pod及合法返回上下文 |
| /ai-config/document-processing | AI | 资料处理用途详情；明确处理空间与范围 |
| /ai-config/search-indexing | 存储空间 | 选定空间的搜索与索引；缺少合法目标时先选择，不默认第一个 |
| /ai-config/index-lifecycle | 存储空间 | 选定空间的维护任务与进度；原策略/执行owner不变 |

在空间任务中组合用途editor时仍留在存储空间；主动打开完整深链才采用上表导航归属，并保留合法返回位置。导航高亮由Shell路由owner唯一决定，不由业务组件各自推断。缺Account不遮住已有WebID/Pod权限允许的区域，具体准入按§4/§7.2。

新窗口没有明确deep link时进入概览。首次状态在概览解释下一任务，不增加强制全局向导；唤回已打开窗口保留当前任务。任务上下文跳转优先于默认页。切换入口保留本次窗口中合法的主题选择；切换身份后不沿用前一对象的敏感内容。

### 3.2 高级能力的归属与可达性

服务详情保留 /status/services/gateway、solid-server、api-server；在“服务与启动”中按需展开/切换，不常驻三条一级导航。日志 /status/logs 在诊断中可直接访问，故障摘要可一键进入相应来源。

用量保留 /status/usage/overview 及 storage/bandwidth/ai/index-storage 深链，按空间/连接明确范围，由相关对象详情进入。搜索与索引保留 /status/index/overview、rdf、fts、vector、retrieval-points、cache、slow-queries、benchmark 深链；空间内给实际搜索状态及维护入口，内部后端和性能维度进入诊断。当前路由决定正确导航上下文，不能因旧路径叫status就退回18项目录。

Network 的端点/地址/DNS/HTTPS/隧道/P2P深链保留为相应任务的详情，不要求用户逐页经过。AI用途深链保留 model-assignments/document-processing/search-indexing/index-lifecycle；它们承载已有业务，不强制为完成一次用途修改依次打开四页。存储、运行、Cloud和Advanced旧目标按当前对象归组；没有真正应用偏好时不新造空“设置”页。

同一编辑器、观测与任务进度有唯一owner，可在原任务中组合呈现并链接完整详情；不得在多个入口复制数据与编辑状态。

### 3.3 历史入口兼容

| 旧入口 | 目标或当前归属 |
|---|---|
| /dashboard、/dashboard/overview、/dashboard/status、/dashboard/runtime | /status/overview；服务详情从摘要可达 |
| /dashboard/logs | /status/logs，服务与访问的诊断上下文 |
| /dashboard/rdf | /status/index/rdf，索引诊断上下文 |

## 4. 页面权限与事实边界

| 页面/操作 | 所需来源 | 不得据此要求或推断 |
|---|---|---|
| Status 的 Account 管理面、CSS Account 页面 | CSS Account | 不启动无关 WebID 恢复，不要求已有 Pod |
| 本机 Network、Runtime 等管理动作 | 已有受保护本机/宿主 authority | “本机”不等于匿名管理权限；不要求无关云账号 |
| AI Connections、Pod 持久化的 AI Config | 有效 WebID 与准确目标 Pod 的访问能力 | Account 成功不构成 Solid 授权；API Key 不构成管理权 |
| /settings/pod 的清单及创建编排 | Account 与该管理动作所需的机器/创建授权 | 零 Pod 不能挡在门外；管理成功不构成 Pod 内容读写授权 |
| Pod 内容、授权资源与持久化配置 | 既有 Solid 授权 | 不用机器控制权或 Account token 替代 |
| 机器控制/后台运行 | 9/19 定义的控制与宿主能力 | 浏览器不持有 service/node 管理凭据 |

同一页面需要多种能力时按区域消费，不合并成新的“全部就绪”会话。Status 中依赖 Pod 的用量区域可显示资源恢复入口，其失败不遮住已授权的服务状态。Account/WebID 两方分别呈现自己的账号、阶段与退出结果。

沿用 canonical：Account 四态、WebID 五态、Pod 八态；本文的“长等待”“上次数据”“未支持”是展示或能力说明，不新增领域枚举。Account 错误不能被改写成 anonymous；WebID/Pod 失败不能清掉另一方会话。原始 WebID 字符串按领域规范比较，不能以展示格式化参与身份匹配。

## 5. 认证、Pod 与任务续接

### 5.1 场景和容器

| 场景 | 固定展示合同 |
|---|---|
| WebID 或简短 Account 登录、恢复、回调 | 280×400 compact 基线；主题画布铺满，16px 内边距；一份 body，无内嵌白卡/遮罩 |
| Xpod Web Account | ≥900px 左产品说明、右表单；右表单最大 448px；<900px 同一 body 单列，说明压缩到必要上下文 |
| 注册、完整 CSS consent、独立 Account 入口中的首次 Pod/Pod 管理 | Account 文档流程，不能强塞 compact；文档单一纵向滚动，不套 Card/ScrollArea |
| 工作区内的 /settings/pod | 存储空间 Content 承载同一 Pod 管理 body；保留 Shell，不嵌套 Account 文档外框 |
| App 承载 Account 文档 | 首次默认 1040×760，最小目标 640×560，受系统可用空间夹限；由宿主路由 owner 选择 |
| 正常短表单 / 长错误或 200% 字体 | 正常无需额外内滚动；内容变长允许一个宿主内容滚动区，保证错误、主动作、返回都可达 |

Pod 管理的容器由显式入口场景决定：Shell 内访问 /settings/pod 使用存储空间 Content；从注册或 consent 进入的独立 Account 场景使用 Account 文档。宿主/路由 owner 持有并在刷新、续接时保留场景标记；它只是展示输入，不是认证凭据或任意外部 returnTo。没有独立场景标记的 /settings/pod 按 Shell 渲染。两种场景共用 body 与创建事务，完成后返回各自经验证的发起位置。

本文件中的 280×400、1040×760、1180×800 及最小窗口尺寸，均指宿主逻辑像素窗口 bounds；断点与内容间距使用内容视口 CSS px。原生标题栏与安全区占用从可用内容扣除；不得用固定内容高度遮住操作。

宿主唯一决定窗口几何；业务 body 不调用 IPC，不通过 localhost、视口大小或登录状态猜测认证场景。用户调整过的同类窗口尺寸优先保留；切换场景只应用对应窗口约束，不反复重置。浏览器认证对话框按实际可用视口夹限，不伪装成桌面窗口。

### 5.2 从注册到创建 Pod

已有发起任务时，持续显示其标题与“继续准备存储空间”入口，复用Account文档和Pod管理body；用户不需要先学会Settings导航。独立注册仍按Account页面落点，完成注册不能隐式创建。读取、校验和绑定发现由系统执行并反馈，不为每一步增加“下一步”。

1. 注册表单仅请求 Account 真实必填项。Account 显示名称若服务要求则保留；Pod 名称、机器、存储选择不混进账号注册。
2. 注册完成进入 Account 页面或canonical允许的合法原授权事务，反馈“账号已创建”；不调用 Local prepare 或自动创建 Pod。只有权威清单确认无绑定才显示“还没有 Pod”。
3. 用户进入 /settings/pod，选择“创建 Pod”。可选位置来自已支持的 Cloud 与本人有管理权的机器；展示部署方式、保存位置和前提，不默认替用户选择未授权机器。
4. 选定机器若 Xpod 已停止，明确呈现“启动 Xpod”及影响；启动后等待真实健康结果。无法确认状态时先恢复读取，不当作已停止或已就绪。
5. 创建确认展示目标位置、目标身份/归属信息和名称等真实必要字段。只有明确点击“创建 Pod”才提交；同一事务沿用 canonical 的幂等标识。
6. 区分“创建请求已提交”“Pod 已创建”“绑定已确认”和“Pod 已就绪”。创建/绑定结果由目标 owner 与权威记录证明；“Pod 已就绪”还须满足 canonical：精确 WebID × storageUrl 与会话一致，且有实际鉴权读写命中该 Pod 的证据。仅有 Account 时只展示已确认的管理结果，不把资源验证设为注册成功的前提；机器在线、目录存在或接口 2xx 都不足以证明资源就绪。
7. 超时、刷新或重复进入先查询原任务与权威清单；不能通过重注册、换名称、创建替代 Pod 来恢复。“取消等待”不表示服务端创建已撤销。

已有 Pod 不可达、读取失败、缺 owner、身份冲突各有原因和恢复动作；缺 owner 只有权威创建记录或已验证控制权才能支持修复，不猜归属。多 Pod 明确选择，不默认第一个。

“绑定已有 Pod”的证明协议仍由 9/19 §4.2 待定义，属于 §11 的单独依赖。当前先提供禁用入口与可见说明“此部署暂不支持绑定已有 Pod”，不要接受一个 URL 后显示绑定成功；协议缺口不阻塞已支持的显式创建流程。

### 5.3 授权与返回

Consent 展示应用、实际请求权限、WebID 和目标 Pod；无 Pod 时提供“前往 Pod 管理 / 取消授权”。去管理只保存有时限、绑定当前 Account 与原 interaction 的安全续接上下文，不自动创建。回来后重新读权威绑定和健康结果；账号切换或事务失效后开始新的合法流程，不续用旧授权。

WebID 登录复用 Inrupt；CSS 决定是否要求 Account 登录。AI Connections 不嵌入另一套 Account 密码表单。完成后回到合法发起任务及所选对象，不无条件跳 Status。密码、令牌、provision code 不进入 URL、日志、通知或普通持久化表单草稿。

## 6. 公共状态、反馈与动作

### 6.1 等待与恢复

首帧先应用正确主题。首次恢复 <300ms 可保留稳定画布避免闪烁；≥300ms 必须显示具体阶段，例如“正在恢复 WebID 会话”或“正在读取 Pod 绑定”；≥10s 增加“仍在等待”、安全返回/查看详情，只有领域规则允许时才提供重试。这些只是展示阈值，不能把 pending 改成 anonymous、重启 OIDC、重复创建或取消远端操作。

普通刷新保留上次有效内容、时间与“更新失败/正在更新”标记。不要清空全页再 skeleton；身份或对象已切换时不得继续展示前一对象的敏感内容。请求返回与当前对象不符则忽略，由当前 authority 重新读取。

| 状态 | 用户可见表达 | 可用动作 |
|---|---|---|
| 已确认空数据 | 说明尚无什么，不使用故障文案 | 存在且授权的创建/连接动作 |
| 未配置 | 缺失项与影响 | 去对应配置，不伪造测试成功 |
| 未支持 | 当前部署/宿主不支持的能力与原因 | 可保留有说明的禁用入口，不显示可执行假按钮 |
| 能力未知/读取失败 | “状态无法确认”，保留可信的上次时间 | 重查来源或诊断；不显示零额度、零资料 |
| 无权限/会话失效 | 指明对象与缺少的权限/会话 | 合法的授权、重新登录或返回；不影响无关 authority |
| 已保存 / 待应用 | 分别显示保存和应用阶段 | 需要时给明确重启/重建动作 |
| 失败/部分完成 | 哪一步成功、哪一步失败、对谁有影响 | 重试失败阶段；结果未知先查原任务 |

### 6.2 表单、取消与破坏性操作

字段有持久标签、单位/范围和必要说明。校验在触碰/失焦或提交后显示，确认密码不在首次输入主密码时误报。保存中防重复；服务器保存失败保留安全输入。成功 inline 反馈与当前操作相邻，不靠瞬时 toast 作为唯一结果。

未保存修改离开页面时，显示“放弃更改并离开 / 继续编辑”；不默默保存，也不阻止无编辑的导航。普通可逆保存不加确认。删除资料、撤销正在用的凭据、停止服务、覆盖客户端配置、重建索引等按实际影响在提交前说明目标、影响与能否恢复；确认按钮写具体动作而非“确定”。

每次仅一个主模态。Esc 关闭可关闭的弹层并恢复触发点焦点；提交进行中若允许离开，明确只是停止等待，不能将关闭弹层视为取消已提交操作。删除成功才移除列表记录；读取失败不清空列表。没有后端撤销能力时不提供假的“撤销”。

Enter 提交当前表单；普通更新用 polite live，阻断当前提交的错误才 assertive；日志流不逐行播报。焦点落在错误摘要或首个错误字段，刷新不抢焦点。动效 120–180ms；reduced-motion 去除过渡，进度仍有可读阶段文字。

## 7. 页面、功能与完整任务合同

### 7.1 概览：按当前情况回答用户

页面稳定分为结论、需处理事项、访问与空间摘要、专业详情入口。刷新不任意重排焦点。机器在线、服务健康、地址可达与空间访问各有依据，不能合并成全局“可用”。

| 情况 | 优先信息与动作 |
|---|---|
| 正常 | 当前实例、精确可用范围、推荐地址与复制、当前空间/位置入口；三服务收为一行摘要。无待办就无大号主按钮 |
| 首次/尚无配置 | 说明当前可做什么，给“管理存储空间”“连接AI客户端”等真正有用的入口；可选AI/公网未配置不制造全局警告 |
| 主动停止 | “Xpod已停止”与获授权的启动动作；不采用故障文案 |
| 局部失败 | 结论后先说明影响与一个首选恢复动作；保留仍可用区域；同一根因不重复画三张服务错误卡 |
| 状态未知 | 上次可信时间、未知范围与重新检查；不冒充全部正常，也不把未知写成空数据 |

服务健康不代表知识已覆盖、模型已训练、release已启用或原Run已完成。知识积累、运行时适应和模型训练沿用R5分别表达；可选未训练保持中性，但当前任务所需模型/空间不可用须就近显示影响与恢复。概览不另造训练仪表盘或合成健康状态。

正常首屏预算是一个结论、最多四组事实、零或一个强调动作，不同时铺满服务/用量/索引/地址卡墙。多个独立问题时显示最高影响项与其余数量，展开完整列表；不能折叠掉会改变当前提交决定的风险。

### 7.2 存储空间：围绕用户的空间聚合

存储空间以 /settings/pod 为入口，复用既有管理body与各区域editor。Account清单、创建与机器编排维持原Account及管理授权；零Pod仍能进入这些管理任务。清单显示名称、位置和关键可用性；选择空间后呈现位置与容量、应用访问、搜索处理、实际支持的备份/导出/迁移。

聚合入口不新增全页Account门禁：已有有效WebID与合法目标Pod时，内容、搜索、用途等区域按各自Solid权限进入；缺Account只在依赖Account的清单/创建区域给登录入口，不能隐藏已授权Pod任务。反过来，Account管理不要求先有WebID。导航与深链采用相同区域准入，未经Account授权不能列出其管理清单，未经Solid授权不能读取Pod内容。

测得的容量和索引占用放在所属空间，而非要求用户去另一工作区拼接；统计未知不显示零。当前区域标出Account、WebID、Pod的实际关系，不能把放在同页误当同一权限。

“查看资料”只有真实支持的内容应用才能提供；只有资源URL时使用“复制存储地址”或专业“打开存储地址”，不假设已有文件浏览器。原始资料、可重建索引、持久模型产物、备份、移除副本和删除空间分别描述。已发布adapter/checkpoint不能随索引或缓存清理；未定义能力不新增破坏性入口。

资产详情给出原资源、来源和版本的稳定定位；日常知识编辑和模型用户操作返回LinX原对象，模型发布仍由Foundry治理。导出说明能带走什么，备份说明可恢复什么，迁移说明源/目标、身份与连接影响。操作前逐类列出资料、知识/任务记录、模型字节与manifest、来源/授权记录、索引及凭据的包含/排除/未知状态；外部artifact store单列可访问性和字节是否纳入。只有引用不能称完整模型备份。完成后分开显示清单生成、字节复制/校验、恢复验证；未验证恢复不报“可完整恢复”。凭据是否随迁移由原安全契约决定，不默认导出。

搜索与处理在本空间中组合状态、用途设置摘要和维护任务，具体模型选择复用AI领域editor；同一事实与任务只有一份owner。以下中间操作见§7.4。

### 7.3 AI：连接客户端是一条连续任务

AI合并顶层入口，保留AI Connections和AI Config的数据/职责边界。无相关配置时以“连接客户端”“为资料处理选择AI”说明任务；已有配置时优先已连接服务、客户端的已知配置状态和实际用途，不每次展示新手两张大卡。全量Provider目录仅在添加时出现，API Keys保留管理入口。

客户端流程：

1. 用户选择目标客户端；读取真实支持的宿主配置能力，列出已有连接/兼容模型。
2. 缺连接时在原任务上下文添加支持的服务；OAuth、导入、API Key按provider真实能力出现。注册/空间/授权若确需补齐则按§5续接，不能让用户自行找回入口。
3. 用户明确选择复用已有Xpod Key，或创建独立命名Key；说明共享影响，不默认重建。客户端获得Xpod endpoint+Xpod Key，不拿上游凭据。
4. 预览目标位置、实际字段、已有值的覆盖范围和恢复方法。显式“应用配置”或“创建密钥并应用”表达此次副作用；无法写入时提前给客户端专用复制方案。
5. 分别呈现密钥结果、配置写入/复制、Gateway检查、客户端验证。Key已创建但写入失败时沿用该Key和原任务，只重试写入；无客户端验证能力时显示“配置已写入，尚未验证客户端”，不能报完整成功。

内部发现、读取与校验阶段显示反馈，不要求每一步都点“下一步”。会触发费用/发送内容的真实模型测试在提交前说明，并由用户明确发起；一般连通检查不假装证明客户端端到端可用。

连接或Key详情显示“正在用于”的**已知**客户端/用途，未知关联不声称完整。停用共享Key、删除连接前说明已知影响和未知范围；列表普通行只放名称、主描述、关键状态，一个直接动作，其余维护操作进入有名称的菜单。不要用Stop图标让用户误以为只停当前客户端。

上游连接失效时，从受影响任务进入修复该依赖；完成后重读原模型/用途状态，按§7.7返回原知识资源、模型版本或Run。不能顺便清Account、换Pod或再建Key。恢复/揭示Xpod Key、Provider凭据、运行秘密按原对象安全契约，hash-only验证记录不变。

### 7.4 AI用途：选择模型时能预测后果

用户入口围绕真实消费者的“识别图片文字”“理解文档”“按意思搜索”等用途。schema有某角色不意味着页面必须展示；专业角色名在详情中保留。概要只放用途、当前模型、可用性三列，生效来源作为副文本，编辑后才出现兼容选项、恢复默认与有边界的测试。

模型的三件事分别表达：**发现的可用模型**是系统事实；**允许使用的模型**是用户限制；**该用途生效模型**是明确选择或有依据的默认。列表排序/第一项不得隐含指定embedding默认。显式Pod赋值、合法部署默认继续可用；无合法确定默认就提示选择，不静默越过允许列表。Cloud目录/endpoint限制和模型标识不变，涉及运行语义的依赖见§11。

个人模型接入另须分开呈现Foundry发布目标、runtime实际可服务版本、客户端当前选择及Run实际使用记录，保留来源与时间；候选不自动加入用途，配置写入不报成已在任务使用。启用/回退沿用发布及用途owner授权，历史Run不因回退改写；无法证明具体运行版本时显示未核验。个人模型标签不绕过Cloud目录、endpoint、能力兼容或允许列表。

更改搜索/embedding用途时，在同一任务内展示：当前空间和资料范围、处理服务及外发内容范围、索引兼容性、可证明的工作量/费用或“尚无估计”、现在重建或稍后处理的后果。新模型索引尚无内容时，按实际语义说明仍可用的文本检索与暂不可用的语义结果，不概括成“搜索全部不可用”或“已完全索引”。

保存配置、安排重建和观察完成分别有结果，但无需用户依次打开Model Assignments/Processing/Search/Lifecycle/Status五页。原处展示同一任务进度与恢复入口，专业索引详情仍可直达。重建必须显式，不删除原始资料。

普通设置只暴露能影响结果的选择：是否处理、处理范围、触发方式和用途模型。后端、维度、队列/缓存策略在专业详情中只读或按实际部署安全编辑能力开放，不能将数据库迁移伪装成即时下拉切换。删除源资料后的派生结果清理是来源与权限一致性要求，不给普通用户“保留已删除资料搜索结果”的开关；同步延迟/失败须明确，不能继续将已删除或失权资料作为可访问结果。

### 7.5 服务与访问：状态和设置围绕同一任务

这是本机管理的正式入口，低频不等于隐藏；也不要求用户先进入Cloud账号才能执行已授权的本机任务。

| 主题 | 同一上下文提供 | 专业信息 |
|---|---|---|
| 服务与启动 | 当前机器的服务摘要、启动/停止/重启、开机启动/自动重启策略、保存与应用结果 | 三服务分别健康、PID、依赖、端点与近期错误；具体控制取决于能力 |
| 访问与连接 | 本机、局域网、外部访问范围；推荐地址、实际检测时间、复制和检查 | canonical/API/Solid/issuer及网卡/IP/端口，完整可复制但不前置成多个目录 |
| 对外访问设置 | 按真实支持的直连/托管通道/隧道等方式呈现必要域名、HTTPS、凭据及影响 | 配置值与检测结果分区；切换只一个活动隧道；公网暴露须明确选择；P2P仅能力具备时出现 |
| 诊断 | 日志、网络检查、相关搜索/索引证据；从当前问题带正确对象与筛选 | RDF/FTS/Vector、检索点、缓存、慢查询、Benchmark按任务展开；不自动跑性能测试 |

服务健康与运行策略、访问观测与配置可以同页，事实和动作仍分清，不复制后端owner。保存不等于应用/可达；手动停止不能被自动重启立即抵消。运行秘密只写或脱敏，托管canonical地址只读，传输地址不改身份标识。

从失败Run进入时携带合法Run、实例、依赖及已有时间范围，只展示有证据的关联；恢复只修该依赖，不自动重跑工作或提交训练。诊断后返回同一Run；waiting_input继续原Run，失败/终态重试由任务owner裁决。训练取消协议未定时不因已有Run取消接口就提供同名操作。

数据保存位置、推理/训练执行位置、模型产物存放位置及设备可达范围分别标明；“本机可访问”不证明本地推理，“Pod保存”不证明内容不会外发。

Logs来源、级别、时间、搜索四个独立筛选；内容区尽量宽，明确历史/实时。无导出/脱敏能力不假造导出按钮。Cloud/节点关系放入受影响服务或空间详情，无实际应用偏好不专门增设空“设置”页。

### 7.6 操作连续性与信息预算

配置与诊断可以复用原业务body/editor在任务内组合，不能在每个入口复制状态。使用明确对象、合法returnTo与当前任务标识，身份切换后重新校验。

| 页型 | 常态信息 | 操作规则 |
|---|---|---|
| 概览 | 精确结论、最多四组事实与相关入口 | 零或一个强调动作；可选未配置不报警 |
| 对象集合 | 名称、一个主描述、关键状态；已配置对象优先 | 选中进入详情；每行最多一个直接动作；批量操作需真实任务和能力 |
| 配置 | 当前对象、当前结果、可编辑选择、影响与保存反馈 | 同一事务一个保存区，dirty时强调；不为每个字段/用途制造主按钮 |
| 诊断 | 对象/时间范围、筛选、证据 | 允许更密；保持14px正文或13px等宽可读；当前修复动作仍清楚 |

同一根因只产生一条主错误；无关的正常能力仍可使用。所有“下一步”必须对应用户有意义的决定或明确副作用，后台查询阶段不计为用户步骤。

### 7.7 原对象交接与恢复合同（R6）

以下是业务路径，不新增URL/schema/API。路由owner复用已有资源标识、合法返回和领域续接机制；无法表达的交接登记§11依赖，不能把对象塞入新的展示副本。

| 原任务 | 本机四入口内路径 | 返回与完成依据 |
|---|---|---|
| LinX知识来源访问或搜索受阻 | 存储空间 `/settings/pod` 获授权目标区域 → 访问或搜索覆盖/用途修复 | 返回原资源与版本；重验读取/训练用途授权，索引就绪不等于模型已训练 |
| 使用已发布个人模型 | AI客户端/用途 → 必要时服务与访问的runtime详情 | 保留release、用途和客户端；发布目标、运行版本、客户端检查分别反馈，返回原资产或LinX工作 |
| Run依赖失败 | 服务与访问 → 同实例的连接/日志/依赖诊断 | 恢复后返回同一Run；人的补充与工作继续仍在LinX，修复成功不冒充Run完成 |
| 带走空间和模型资产 | 存储空间 → 实际支持的导出/备份/迁移及范围清单 | 返回原空间或模型详情；外部产物字节与恢复证据单列，Foundry保留发布/退役控制 |

续接保存原对象标识/版本、用途、目标客户端、安全输入、已完成步骤和合法返回位置，不保存秘密到URL。返回前重验身份、权限、材料版本/范围、执行位置、成本与启用范围；变更影响原决定时先说明并让用户重新选择，不自动提交训练、扩大授权、替换模型、再建Key或创建替代Pod。身份切换不恢复旧敏感内容。

修复依赖、继续同一Run、重新发起训练是不同动作。响应丢失先查询原operation/Run/训练作业，已完成副作用不重复；取消等待仅离开等待，取消请求只有领域事实确认后才显示已取消。Run的cancelRequested与worker终态按[任务契约](../../task-system-design.md)；训练取消/重试未定时登记Foundry依赖，不套用Run接口补造能力。资料读取权不推导训练用途授权；撤回授权不声称权重已遗忘。

费用和资源影响在会改变决定的步骤出现，不扩成常驻卡墙。估计费用、实际用量、provider配额、API Key消费和空间容量各列对象、周期、单位、来源/时间；未知非零，不以API余额推导训练可运行，不静默迁移执行位置或换模型。Account用量仍守Account权限。

### 8.3 页型决定布局，尺寸保证可用

| 宽度/页型 | 布局 |
|---|---|
| ≥768px 基础 | 184px有文字的全局导航+内容；概览、固定配置、诊断不强加主题中栏 |
| ≥1100px 真正对象集合 | 有持续比较/切换需求时增加224px对象列；Pod/服务连接等适用，静态章节不算对象集合 |
| 768–1099px 集合 | 保留184px全局导航，列表/详情采用共享stack；明确返回所来列表及滚动位置 |
| <768px | 48px顶部任务栏含标题/返回/有名称的导航按钮；导航抽屉复用同一树，不强制底部Tab；文字放大时允许任务栏增高 |
| Content padding | 宽窗24px，窄窗16px；工具页按证据宽度展开，表单遵循§8.2宽度 |
| 首次工作区窗口 | 保留1180×800作为初始设计目标，最小640×560，受可用屏幕夹限并保留用户尺寸；不是已通过实机适配的声明 |

集合页在1180px下扣184px导航、224px对象列、48px内容内边距，净内容约724px，可容纳640px表单。概览/诊断直接获得额外的224px空间。本机控制器首层只有四个任务入口；二级主题按当前任务展开，不把18个专业维度永久铺开。

知识来源精读与模型评估对照属于内容阅读/比较任务，可复用公共主题、布局和控件，但不强制成为紧凑诊断表，不在本机控制器复制LinX/Foundry编辑页。短认证窗口尺寸只约束认证；资产入口返回原对象。

布局组件共用这四种页型，不允许各模块以“自适应”为由各造导航。对象列、内容在宽屏可各自滚动；stack中当前主面板一个纵向滚动区。宽表在表区域横向滚动，页面不横向溢出。缩放、断点、列表数量变化不夺焦点、不丢草稿；删除最后一个对象回其空态，不突然跳到另一任务。

认证保持§5的独立场景；280×400短流程不带全局导航。正常、异常、配置和诊断可以有不同密度，但共用字体、焦点、控件与反馈语法。

### 9.1 资产合同

品牌源资产在 [homepage/public/brand](../../../../homepage/public/brand/README.md)。由一个资产负责人导入产品资产位置并记录源文件与校验值；不要求产品运行时依赖另一个仓库，不由各页面复制一份几何。

| 用途 | 输入与处理 |
|---|---|
| App / Dock / 安装包 | xpod-app.svg/png 墨紫底留缝折角；固定品牌色，系统包装只做规定的安全区与格式适配 |
| 产品配对展示 | xpod-app-light.svg/png；16/24px 使用同名专用小尺寸资源 |
| 内容单色符号 | xpod-symbol.svg；按主题用正文/操作色；固定底图场景可用 ink/paper 版本 |
| macOS 菜单栏 | 从单色标生成透明黑色 alpha template，16/32px，约 2px 视觉安全区；由系统处理明暗，实施时验证小尺寸轮廓 |
| Windows / Linux | 由桌面资产 owner 按已有平台链生成透明底和所需缩放尺寸；无 tray 能力时保留窗口入口，不虚构菜单栏 |
| 历史 Logo | 旧资源及探索稿保留，切换引用；金唱片、盾牌等旧说明不再作为新图标目标 |

16px 主符号不承担所有状态编码。异常/降级/未知可叠同一种单色关注标记，精确状态由 tooltip、菜单首行与逐服务行表达；不增加红绿橙点，不把网页 SVG 的存在算作系统打包完成。

### 9.2 托盘内容

默认菜单只呈现当前实例及精确运行摘要、打开Xpod、与当前情况匹配且有权限的启动/停止/重启、查看详情/诊断、按§9.3命名的退出动作。不再复制完整四入口导航和三条正常服务。可适用时给复制当前推荐地址；需要进一步配置就打开带正确上下文的页面。

有服务异常时展示受影响服务与下一步，完整三服务状态从详情可达。tooltip和Status消费同一来源/时间。示例“3/3服务运行正常”只描述健康，不声称公网可达或Pod已授权；停止是可管理状态。

### 9.3 生命周期按实际宿主能力表达

| 动作/部署 | 界面行为与文案 |
|---|---|
| 关闭窗口 | 隐藏到仍存在的桌面宿主/托盘，不改变服务；平台没有后台窗口保留能力时不能假称仍在运行 |
| 独立代理已可用时退出 UI | “退出界面”，说明 Xpod 服务继续运行；不结束代理 |
| 当前 UI 进程仍拥有 runtime | 保留“隐藏窗口，后台继续运行”；真正退出用“退出并停止 Xpod”，提交前说明受影响应用/任务，不显示“退出后仍运行” |
| 服务由外部进程/服务管理器拥有 | “退出界面”，不杀外部服务；单独停止动作只有控制权和实际能力具备时可用 |
| 停止 Xpod | 明确停止的机器/服务及影响；停止结果按观测确认，不删除资料，不等于退出账号 |
| 产品级退出登录 | 复用 9/19 已定义的 logout coordinator；列明各 authority 的退出结果，只重试失败阶段；不创造组合 session |
| 单层退出 | 用“退出管理账号”“断开 WebID 会话”等明确名称；只调用对应 authority，不隐式退出另一层或停止机器 |
| 产品级切换账号 | 遵守 canonical X-1：先隔离并清理旧 WebID/Pod，再呈现新身份；不能将单层退出规则套用成保留旧身份绑定。退出失败时改点切号另见 §11 |
| 停止/退出后台代理 | 仅在实际支持时作为独立高级动作，说明失去远程启动能力；不能混入普通退出 UI |

停止、重启、升级或退出前，按已知依赖解释本机Run、远端训练、未来调度及仅UI观察的不同影响；关联不全标明未知范围。退出UI不等于暂停Task、撤权或取消远端作业；本机停止不能显示远端训练已取消。只按真实能力提供暂停/等待/取消选择。维护后重查原任务和模型运行版本，不默认所有任务自动恢复，也不重提结果未知的操作。

服务页面尚未加载时，由桌面宿主渲染本地可用的启动/连接反馈，沿用 §6 展示时机，说明当前阶段及可用诊断。不得只让用户等待原生加载失败页；只调用已授权且实际存在的宿主启动/重试能力，不启动竞争实例。UI 展示时机不缩短既有服务恢复协议的超时，也不改变登录状态。

判断依据是可信的宿主能力/所有权，不凭版本号、进程名称或一个地址猜测。能力未知时保留安全的关窗/返回，不承诺后台存活；不得先退出再让用户发现服务消失。独立代理目标仍按 9/19 实施；本表仅让过渡版本说真话，不降低目标。
