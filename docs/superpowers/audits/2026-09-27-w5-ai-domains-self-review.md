# W5 AI 两域 · 设计自查与实施范围

### 范围与职责

- 模块 / 负责人：AI 一级入口与 AI Connections / AI Config 两个领域（W5）
- 审查日期 / 纲领与实施 spec 版本：2026-09-27 / 纲领 R2、实施 spec 2026-09-27 R2
- 适用设计决定 D 编号 / 实施验收 AC 编号：D-09；AC-05、AC-10、AC-11、AC-13
- 用户任务（一句话）：把客户端接到 Xpod 并在同一处为资料用途选好模型，同时知道这一步会不会外发、要不要重建
- 场景：桌面工作区内的 `/ai-connections`、用途详情（`/ai-config/*`）、窄窗
- 本模块负责 / 不负责：负责 AI 入口的任务组织、客户端接入连续任务、用途与模型选择的前端表达；不负责 provider 协议、凭据存储协议、模型解析与持久化语义（AI 领域 owner 按 §11 提供证据）
- 前置模块 / 完成后去向：W1 公共视觉、W2 页型与导航、W4 概览与空间（AI 摘要消费方）；W7 集成与发布证据
- 审查层次：文档 + 前端表达（读取 `packages/ai-connections/src`、`ui/src/pages/settings/ai-config`、`ui/src/extensions/ai-connections-host.ts`；未启动应用）
- 已阅读的文件、章节或行号：
  - `packages/ai-connections/src/AiConnectionsList.tsx`（268 行：搜索 + provider 目录开场）
  - `packages/ai-connections/src/AiConnectDialog.tsx`（192 行：按 offering 的连接与授权步骤）
  - `packages/ai-connections/src/AiApiKeyPool.tsx`、`AiClientConfigurationSection.tsx`（Key 与客户端配置各自成节）
  - `ui/src/pages/settings/ai-config/ModelAssignmentsPanel.tsx`（用途/能力选择 + embedding 切换与重建提示）、`AiConfigContext.tsx`
  - 实施 spec §7.3、§7.4、§8.1、§10、§11、§12 W5；AC-05/10/11/13；纲领 XP-01/XP-04/XP-10
- 未覆盖范围：真实 provider 授权与额度、模型解析与持久化语义（依赖 AI 领域 owner）、Pod 目录内容归属（models 仓库）

### 功能与操作是否成立（先于规则合规）

| 功能 / 入口 | 用户要作的决定 | 没有它哪条任务受损 | 判定 | 理由和受影响能力 |
|---|---|---|---|---|
| AI 一级入口 | 连接客户端，或为资料选择 AI | 用户要先理解"连接"与"配置"两个模块 | 保留（需重排） | 现状入口以目录开场（E-05） |
| 连接客户端 | 复用已有 Key 还是新建、配置写到哪里 | 常见结果是重复建 Key、或配置写了但客户端没用上 | 合并（需连成一条任务） | 连接、Key、客户端配置分散在三个组件（E-06） |
| 用途与模型 | 该用途用哪个模型、是否重建 | 勾选/排序可能被误解为改变生效模型 | 保留（需改文案与结构） | 现状按技术能力列（E-07），用途信息只在 description |
| Key 与连接的维护 | 停用会不会影响在用的客户端 | 用户不敢停用共享 Key | 缺证据 | "正在用于"与影响说明未核对（E-04） |

### 结论

- 最重要的设计结论（不超过三项）：
  1. 入口与连接流程需要按"把客户端接上"重排，这是 W5 的核心（P1）；
  2. 连接客户端缺分阶段结果，是"Key 建好了但客户端没用上"的根因；
  3. 用途页要按真实用途组织，技术角色名下沉；运行语义仍由 AI 领域 owner 保证。
- 值得保留的设计：per-capability 赋值 + 系统默认的组合；embedding 切换时的重建提示与 flow 测试（`ModelAssignmentsPanel.flow.test.tsx`）；provider 目录只存在一份实现。
- 本模块可修正事项 / 公共层事项 / 待决定事项：可修正 01、02、03、04；无待用户决定事项。
- 本次仍缺少的设计或前端材料：客户端接入四段结果的用例、用途概要的窄窗走查。
- 本轮结论范围：文档 + 前端表达审查；未运行应用。
