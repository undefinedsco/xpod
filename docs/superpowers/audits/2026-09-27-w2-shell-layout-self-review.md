### 范围与职责

- 模块 / 负责人：extension-sdk 布局协议 + Xpod Shell/宿主路由（W2）
- 审查日期 / 纲领与实施 spec 版本：2026-09-27 / 纲领 R2、实施 spec 2026-09-27 R2
- 适用设计决定 D 编号 / 实施验收 AC 编号：D-01、D-06；AC-04、AC-05、AC-06、AC-14（本轮不冒充已做运行验收）
- 用户任务（一句话）：从四个任务域进入，页面说自己正在管哪台机器/哪个空间，并把专业细节留在可直达处

- 本模块负责 / 不负责：负责四入口导航、四种页型与断点、历史入口映射、窗口场景；不负责主题参数（W1）、Account/Pod 流程（W3）、各工作区内容（W4/W5）

- 审查层次：文档 + 前端表达（读取 `ui/src/layout`、`ui/src/App`-级路由与 `packages/extension-sdk/src`；未启动应用）
- 已阅读的文件、章节或行号：
  - `packages/extension-sdk/src/layout.ts`（`AppletLayoutType = 'single-pane' | 'two-pane' | 'three-pane'`）、`packages/extension-sdk/src/react/workspace-layout.tsx`、`manifest.ts`、`web.ts`

### 功能与操作是否成立（先于规则合规）

| 功能 / 入口 | 用户要作的决定 | 没有它哪条任务受损 | 判定 | 理由和受影响能力 |
|---|---|---|---|---|
| 四个任务入口 | 选任务域，而不是选内部模块 | 用户要先把"连不上/搜不到/空间满"翻译成后端名词 | 保留（需合并） | 现状五入口把 AI 拆成两个、把存储埋在 Settings（E-07） |
| 对象列 | 决定是否需要在同类对象间切换 | 没有集合的页面多出一次选择并挤掉内容宽度 | 条件显示 | 现状协议没有"是否真有集合"的表达（E-08） |
| 历史深链 | 不需要决定 | 旧书签/文档入链会断，或落回错误上下文 | 保留（需映射） | §3.3 的迁移表尚未核对落地（E-02） |
| 窗口场景 | 不需要决定 | 紧凑认证窗口与工作区窗口混用会挤掉操作 | 保留（需对齐） | 现状窗口约束与 §5.1 尺寸未逐项对齐（E-09） |

### 结论

- 最重要的设计结论（不超过三项）：
  1. 一级导航必须按任务域合并为四项 + 身份入口，这是 W4/W5 的前置；
  2. 布局协议要能表达"该页是否有真正的对象集合"，否则永久中栏无法撤销；
  3. 断点与历史映射都缺单一依据，属公共层补齐项。
- 值得保留的设计：`workspace-layout.tsx` 已把布局做成可复用协议；`window-mode.ts` 已区分紧凑认证与工作区窗口。
- 本模块可修正事项 / 公共层事项 / 待决定事项：可修正 01、03、04；公共层事项 02（与 extension-sdk 协同）；无待用户决定事项。
- 本次仍缺少的设计或前端材料：四页型的窄窗/键盘验收材料、旧深链的真实走查记录。
- 本轮结论范围：文档 + 前端表达审查；未运行应用。
