## A. 首屏信息优先级（AC-14）

| 步骤 | 期望 |
|---|---|
| 打开 概览 `/status/overview` | 首屏**恰一个结论**（运行正常 / 服务未就绪 / 对外访问需检查 / 状态无法确认之一），最多四组事实，正常态没有大号主按钮 |
| 制造一个失败（例如停一个服务） | 只出现**一张**需处理卡片；若有两类独立问题，出现「还有 N 项」并点名第二项 |
| 展开「专业详情」 | 服务明细、访问路径、Cloud 与配置默认收起，展开后可达 |

## B. 窄窗与 200% 字体（AC-03/AC-06）

| 步骤 | 期望 |
|---|---|
| 窗口缩到 <768px | 顶部 48px 任务栏（返回/标题/有名称的导航按钮）；点导航按钮出现抽屉，抽屉里是同一棵导航树；**没有**底部 Tab |
| 浏览器 200% 缩放 | 正文不截断；错误、主动作、返回都在一个宿主滚动区内可达 |
| 认证短流程 280×400 | 主题画布铺满、16px 内边距、**无内嵌白卡与遮罩**（画布/正文色与"无卡片"已由 `accept-r2-login-surface.ts` 覆盖；280×400 的窗口形态仍需真机确认） |
| Web Account ≥900px / 更窄 | 宽时左说明右表单（表单 ≤448px）；窄时单列 |

## C. 菜单栏与 Dock（AC-02/AC-12）

| 步骤 | 期望 |
|---|---|
| 切换系统浅色/深色 | 托盘五态（正常/启动中/部分运行/异常/已停止）在两种菜单栏下都可辨；状态由图形+文字表达 |
| 停掉一个服务 | 托盘出现「查看 <服务> 日志」并直达带 source 的日志 |
| 关闭窗口 | 服务继续运行；托盘菜单里「关闭窗口后服务继续运行；退出 Xpod 才会停止服务」与实际一致 |
| 退出 | 确认框写明会停止服务；退出后服务确实停止 |
| Dock | 图标与选定品牌一致；选定前的旧资产仍在品牌仓归档中 |

## D. 空间与 AI 任务闭环（AC-07/AC-09/AC-13）

| 步骤 | 期望 |
|---|---|
| 注册新账号 | **不**自动创建 Pod；账号管理页可进入（零 Pod 也可）；只有点「创建」才提交创建 |
| 空间详情 | 位置、用量、访问、搜索处理在同一空间上下文；用量未知时显示「状态无法确认」，**不显示 0** |
| 连接客户端 | 入口先选客户端；选「使用我已经有的 Key」时**不新建 Key**，配置以可复制文本给出；选新建时给出四段结果（密钥/写入/网关检查/客户端验证） |
| 写入失败后重试 | 沿用同一个 Key 只重写配置（API KEYS 里不会多出一个新 Key） |
| 改「按意思搜索」模型 | 同一任务内看到影响说明与重建选项；保存后能观察到重建状态 |
