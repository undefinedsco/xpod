# Installed bundle proof uses original tar bytes

`verifyInstalledBundles` validates the seven required embedded packages against the original root archive, including every file's SHA256 and the installed file's realpath containment. It reads tar header names, types and payloads through the existing `workspace-package-payload` parser. It no longer parses system `tar` listing text or extracts scratch directories.

The original Windows failure on head `42e94f338f9224d680a31107453dc871c694cb42`, actual checkout `1314f9b97dfdcd58bf58570974aa623f20737815`, Legacy run `38863504645` attempt 1 occurred after root plus eleven private packages had installed. `verify-installed-bundles.cjs` rejected its native listing tables as `Unsafe bundle proof archive`. The tables' original stdout/stderr were not retained: CRLF is a candidate explanation, not a proven historical byte-level cause. This change removes that text protocol dependency; real Windows acceptance still requires new CI originals.

The shared parser requires lossless UTF-8 in name/prefix fields and preserves literal trailing spaces. Invalid sequences and multibyte truncation fail; a real U+FFFD character remains valid and distinct from a decoding replacement. Numeric fields retain strict octal parsing. The bundle caller rejects all archive control characters, non-`package/` paths, links, special entries, traversal, duplicate names, corrupt/truncated archives and missing bundles. Installed directory entry spelling is checked before realpath resolution so a host's case or trailing-space alias cannot stand in for the original archive name. Matching links within the installed Xpod root retain their existing behavior; external realpaths fail.

The caller's fixed compressed bound is 128 MiB, matching the existing root-archive binding in `root-registry-supply.verifyBuild` and retained root readback. It is a root archive bound, not the separate 16 MiB normal AFS supply acquisition limit. Expanded tar output is capped at 256 MiB and 100,000 entries. Optional shared-parser limits are validated; existing callers without limits retain their existing byte-budget behavior. The verifier reads one compressed buffer and performs one bounded inflate; entry payloads are views of the returned tar buffer, with no extraction or second whole-archive read. These bound application payload buffers (128 MiB compressed plus 256 MiB expanded), not total process RSS or zlib's transient internal allocations.

The retained Windows root archive is 10,156,943 bytes, SHA256 `dacbb961d8993c95b5196fa19176836efd2144a88d931dfdf33d9cf1345da1f9`. Its expanded tar is 52,060,672 bytes and contains 7,012 entries. A local probe strictly parsed that original and copied only the seven bundle payloads (700 files) into a fresh fixture for comparison. This proves archive parsing and fixture comparison, not the historical installed consumer tree, which was removed. The separate archive-read authorization was limited to that one compressed member at 16 MiB; it does not grant broader evidence downloads.

## GNU long names in normal Linux root packs

The normal Linux root archive on head `75e0536767c92a958a2d00a0164b8e57b3fef560`, actual checkout `b4b4fd29c49772b9a3414bd2153369de177f6f60`, Legacy run `38870574142` attempt 1 contains GNU `L` headers named exactly `././@LongLink`. The earlier strict buffer parser rejected this metadata after the real package install completed. A bounded walk of the original 10,427,246-byte archive (SHA256 `2adb9d87bea3777834b05d05f8bd731b40c2df6e06856d2bab0378d7b54f94d4`, expanded 52,992,000 bytes) recorded 7,899 headers including 886 long-name metadata headers, whose largest payload was 211 bytes. Original metadata headers, payloads, next headers, offsets and hashes remain retained.

Only the root bundle caller enables the optional `gnuLongNames` buffer-parser flag. The metadata header's checksum, numeric fields, exact marker and type are checked. Its name payload is bounded to 4,096 bytes, must contain exactly one terminal NUL, and must decode as lossless UTF-8 with a safe relative path and no controls. It binds only the next regular file or directory; that entry still has its own valid checksum, type, raw header path and effective path. Duplicate detection uses the full effective name. Metadata counts against the header budget and is never a payload file or manifest. Consecutive or dangling metadata, malformed/oversized names, links and other special types remain rejected. GNU link targets (`K`) and generic PAX support are not added.

Existing buffer callers do not enable GNU handling by default. The streaming inspector continues to call the shared header validator without metadata interpretation and fails closed on GNU `L`; its regression test explicitly checks this. No streaming entry may silently become metadata or a manifest through this change. Real Linux original-archive probing copies only the seven bundle payloads to a fresh fixture; historical consumer trees remain unavailable, so new full Linux and Windows consumer evidence is still required.
