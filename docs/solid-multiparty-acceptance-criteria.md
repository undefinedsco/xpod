## 已定设计与比较口径

- 用户身份直接使用 WebID；Agent 使用其明确的身份 URI，执行者通过当前 Agent grant 证明代表关系。
- O1：部署使用参与者明确授予的 Solid 凭据，以参与者身份调用对端；不回退到部署身份或冒用其他参与者凭据。
- `(roomId, eventId)` 是逻辑唯一键。客户端 `msgid` 与服务端自发事件均由写入方命名，不再以事件内容哈希充当事件 id。
- 相同逻辑键、相同事件语义返回原事件；不同语义拒绝且保留原记录。单事件写接口返回 409；
  批量 `PUT /send/{txnId}` 沿用逐条应答，冲突项必须明确拒绝，不能因整批 HTTP 200 而算作已接受。
- 重试比较至少包含 `sender`、`type`、`state_key`、`content`；另一个作者不能借相同正文占用已有身份。
  事务 id、接收时间、本地分桶、租约及投递记账不改变事件身份；重试不重新生成原事件的时间或内容。
- C2：成员、角色和房间元数据以房主 Pod 为权威；其他 Pod 的成员镜像只供读取展示。
- 拉取是可靠传播路径，推送只是可选提醒；HTTP 投递保留 Matrix 的 PUT 形状与 `/_matrix/*` 前缀。
- 保留 models 共享日文档布局：单条消息由 `messages.ttl#…` 主体标识，metadata 等嵌套主体也必须唯一。
- 事件内容哈希用于核对内容；不要求每事件签名、部署密钥托管或 Matrix v11 状态解析。

## 核心指标

表中数字是验收数据集或不变量；开发者不得据此把可支持的业务规模限制为该数字。
每个指标报告测试名称、实际环境和结果；自动化与真实实例证据分别列出。

| 编号 | 指标与通过条件 | 最少验证场景 / 证据 |
| --- | --- | --- |
| G01 身份 | 新事件的用户 `sender`、成员与角色键均为 WebID；跨 Pod 保持同一 `roomId/eventId/sender`；Agent 身份不被改写为部署或用户身份 | A/B/C 三个不同 WebID、三个独立 Pod，至少两个独立 API 部署；成员、用户消息、状态、助手结果各验证一次；主路径不产生新的 `@u_<hash>:host` |
| G02 O1 与 Pod 授权 | 真实跨域 Solid 认证成功；缺凭据或无效凭据拒绝；冒名、无成员资格、无 Pod 写 grant 拒绝；拒绝请求产生 **0 条新增消息、0 个新增任务、0 次执行副作用** | 正向跨部署 PUT；匿名/失效凭据/错身份/非成员/无 grant 五类负例；grant 撤销成功后，下一次 claim、续租、提交和写入重验权限；不能只测 helper |
| G03 事件幂等 | 每个逻辑键在每份参与者 Pod 中仅有 **1 条消息主体**；相同语义返回原 id、内容与首次创建时间；不同语义拒绝，原记录不变 | 同 txn、不同 txn、跨日、跨请求身份、响应丢失后重试、服务重启后重试；同键 **16 路并发**，同内容与竞争内容各跑 **3 轮**；跨日/并发必须至少有真实 RDF 写入证据，内存 insert 去重不算存储保证 |
| G04 全部事件命名 | 用户消息、create/join/invite/成员变化、业务状态和助手结果均由写入方命名；重试复用 id；副本不改名 | 每类事件验证 id 来源与重试；一个唤醒始终对应一个助手结果身份；主路径不再使用 `computeEventId` 作为内容哈希命名回退 |
| G05 房主权威 | 改成员/角色/元数据仅由房主或房主当前授权主体提交到权威 Pod；权限检查依据当前权威；无法确认权威时拒绝新的写入/执行 | 本地镜像伪造 join、镜像角色过期、房主 Pod 不可读、成员移除、普通参与者改房间五类负例；重连后刷新镜像；不强行停止已完成的合法在途操作 |
| G06 拉取传播 | 关闭推送提醒后，依靠订阅/拉取及断线对账仍使所有有权限的副本最终收齐事件；重复通知不产生重复消息；不依赖入站回执或出站欠账批次 | 同一共享日文档先创建再追加，两种变化均被发现；丢通知、重复/乱序通知、订阅断线、离线期间新增、跨日新增、晚到旧日期事件；**72 小时和 8 天逻辑离线**两组场景，分别跨过旧 2 天/7 天查找窗口边界 |
| G07 内容真实性 | 从作者之外获得的副本不能自行成为可信正本；按 E3 找到作者 Pod，并核对内容哈希；查不到、读不到或内容不一致不得接受为已确认事件 | 直接作者的已认证投递、拉取作者正本、第三方副本、篡改正文、错误作者源、作者不可读、作者无此事件；比较复用已有规范化/哈希规则，不另造一套 |
| G08 RDF 与父容器 | 不改变共享 models 布局；同一日文档消息/metadata 主体隔离；首次资源写入前完成必要父容器准备；新文档可列举和订阅 | 空 Pod 新房间/新日期；同文档 **100 条消息**各带不同正文及 metadata，包含引号、Unicode、回复与 mentions；真实 Turtle 与 ORM 回读逐条一致；更新一条不污染其他 **99 条**；父容器 `ldp:contains` 与通知证据 |
| G09 唤醒与恢复 | 副本数量不增加独立执行数量；执行者凭据、当前 grant、触发内容和租约均验证；每个逻辑唤醒最终仅 **1 个助手结果**；终态不复活 | author→reviewer 两个不同执行者身份交接；错执行者、撤权、触发被改、旧租约提交拒绝；claim 后、结果写入前、结果已写/确认前、交接前四处中断；清空可重建队列后恢复；外部工具至少一次执行，不宣称副作用天然恰好一次 |
| G10 分页、增量与有界读取 | 相同 Pod 上按 `(createdAt,id)` 稳定排序；分页合并无漏、无重；晚到和同毫秒事件最终可见；变更发现不能依赖客户端传回全部历史 id | **200 条事件**，其中至少 **20 条同毫秒**、**20 条晚到**；limit 分别 **1/7/20**，逐条核对 id 与正文；重连及本地索引重建后用旧 token 继续或显式要求重同步，不能静默跳过；读取计数门禁见下节 |
| G11 删除与迁移边界 | 新路径无需每事件签名、密钥托管、事件事务预留、入站回执、出站批次和 v11 状态解析；保留必要的可重建本地索引；历史数据处理必须明确且不静默改写 | 静态依赖审查 + 删除对应设施后的启动/协作恢复测试；移除预留前，入队内容回执与助手唯一结果职责已有替代证据；旧 MXID/id/token/控制记录逐类说明读、迁移或拒绝行为；原生第二投递路径不存在 |
| G12 全链路与回归 | 实际 Gateway 的运行时、身份、Pod 读写、O1、房间、复制、分页与 Agent 交接分别通过；相关自动化门禁 **0 失败**；核心场景 **0 跳过** | 当前用户实际 Gateway 至少参与一端，记录运行构建；另一端是独立部署及身份。已有 **63 事件**协作闭环保持 id/正文、两份结果、分页和重复完成拒绝断言；再运行下面的完整回归命令 |

G09 的清空范围为可重建的 Matrix／执行索引与队列，不包括凭据 vault、撤销和版本历史或 Pod 权威事实。重建使用当前合法的 owner、成员／Agent caller 或已有显式可信 dispatch；没有合法读取主体时验证零新写入／执行，恢复授权后继续同一 Run，不复活终态或重置预算。不得将“非秘密 Pod 指针可重建”表述为“凭据库全部丢失仍自动恢复”。

## 有界读取与性能记录

先证明正确性与读取工作量边界，不依据内存 harness 的毫秒数宣称生产吞吐。

1. 正常订阅工作、未到对账周期且没有变化时，空闲等待循环 **不追加事件数据的 Pod 读取**。
   认证和权威成员检查单独计数，不能通过缓存撤权判定换取“零读”。
2. 已完成初始索引的 Pod，比较 **10 / 200 / 1000 房间**；只改一个房间、读一页时，
   读取的房间历史数量恒为 **1**，无关房间历史读取数为 **0**。请求计数逐项报告。
3. 同一房间分别准备 **200 / 2000 条历史事件**，追加同样 **20 条**；正常增量不能重新扫描整个 Pod。
   API 一页最多返回请求 limit 条消息。对共享文档的 GET/hydration，分别记录请求数、文档字节和反序列化行数，
   不把“返回 20 条”当作“底层只读了 20 条”的证据。
4. 冷启动、索引重建及丢通知对账可以做扫描，但必须分桶/分页、有持久恢复边界，并与正常增量分开记录。
   72 小时、8 天离线与晚到事件测试完成后核对整个期望集合；不能用缩短回看窗口取得有界假象。
5. 客户端 token 必须有与历史事件数无关的大小边界；报告 200/2000 条时的字节数及上限的实现依据。
   若按房间保存水位，另报房间数量对大小的影响；不得把全部历史事件 id 塞进 token。
6. 对真实实例的本地写入、跨 Pod 可见延迟、分页、恢复分别报告样本数、p50/p95/max、网络与存储环境。
   每项稳态采集至少 **30 个样本**；这是测量要求，尚未设定未经验证的延迟 SLO。
   正常通知恢复不采用无限等待：记录实现的重连/对账周期 R、批量拉取预算 L，故障测试应在有限的
   `2R + L` 预算内完成；夹具可注入时钟，真实实例必须记录实际 R/L 和截止时间。

## 最少故障矩阵

每项运行结束核对：期望 id 集合、实际消息数量、正文/哈希、任务与结果终态、拒绝后的零变更。
“HTTP 200”“轮询超时前没有报错”或“最后一条已到达”都不能代替集合核对。

| 故障 | 通过条件 |
| --- | --- |
| 写入已成功但响应丢失 | 用原 id 重试得到首次记录；不新增第二条、不重新运行 Agent |
| 同键竞争与跨日重试 | 首次成功的内容保留；竞争不同内容被拒；每份 Pod 只有一个该逻辑键 |
| 订阅断线且漏掉日文档更新 | 重新订阅/对账补齐；同文档追加和跨日新文档都不漏 |
| 拉到一半、游标确认前崩溃 | 恢复后重拉同批不重复，游标不能跳过尚未持久化的事件 |
| 房主不可达或权限撤销 | 新的写入/claim/续租/提交不凭旧镜像放行；恢复授权后可继续 |
| Run 结果落 Pod 后崩溃 | 读原结果并补终态；结果身份稳定，交接只沿原逻辑执行继续 |
| 可重建 SQL 索引/队列丢失 | 在独立验收 scope 重建后集合与终态一致；不复活 completed/failed，不重置尝试预算 |
| 作者副本不匹配 | 拒绝或明确保留为未确认状态；不能进入可信 timeline 或触发执行 |

## 证据交付与最终复核

开发证据报告写入 `docs/solid-multiparty-implementation-evidence.md`；原始测试数据和脱敏报告放
`.test-data/solid-multiparty-acceptance/<run-id>/`，不进入项目根目录或提交秘密。
报告至少包含：

- 交付 SHA、工作区变更状态、Bun/Node/依赖版本、命令与退出码、日志位置。
- G01–G12 各行的 `passed / failed / not_verified`、测试名称、覆盖数据量、实际观察值及跳过原因。
- 实际部署构建、Gateway/CSS/API 状态、不同 WebID 与 Pod URL；全部凭据、token、secret 脱敏。
- 各 Pod 的事件 id 集合/摘要、记录数、正文比对、冲突响应与拒绝后的零变化；故障注入点与恢复耗时。
- 旧测试到新契约的替代清单、删除模块及被替代的承重职责、剩余缺口。

主负责人最终复核：读取实现 diff 与证据覆盖，独立重跑关键负例、跨 txn/跨日并发、RDF 回读、撤权、
恢复和多身份交接；检查完整回归命令及真实 Gateway 结果确实对应交付代码。开发负责人不得自行修改指标来匹配现状。
更改设计需给出问题与证据，由主负责人处理；没有独立复核结果之前，最终状态保持未验收。
