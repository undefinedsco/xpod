# Desktop runtime build inputs

The desktop installs the normally packed CLI and client. CSS/API/AFS remain
ModuleStore capabilities. A packaged app runs its CLI with `runtime/bin/bun`;
missing bundled Bun is an incomplete app, even when system Bun exists.
Unpackaged use retains the normal CLI launcher and its Node/Bun contract.

Run `bun run --cwd desktop dist`, or `build:runtime` then `pack`. `build:runtime`
composes `init:runtime`, the ONE initializer that derives every identity from the
reviewed Bun 1.4.2 pin and writes the descriptor under
`desktop/.test-data/runtime-input/`. By default it downloads the pin's own
official archive (cached by digest); `bun scripts/init-runtime-input.ts
--archive /path/to/bun-darwin-aarch64.zip` reuses a local copy instead. No user
environment variable and no caller-supplied digest/target/version is accepted.

`stage-runtime.ts --runtime-input /absolute/input.json` still accepts an explicit
descriptor, so a custom producer can drive staging directly without this
initializer. That is the supported entry for anything other than the pinned
runtime.

**Qualification scope.** The checked-in policy in `desktop/runtime-materials/`
is the single authority: `manifest.json` names every original with its pinned
source URL and SHA-256, plus the full pinned Bun source archive identity. When
that assessment is reviewed and `verified`, the initializer emits `release` and
stable `dist` consumes it with no extra flags, workflow download or user
environment variable. An unreviewed assessment can only emit
`controlled-preview`, and asking for `release` with unreviewed material is
refused, so a preview runtime cannot silently become the stable default.

`verified` means the declared original set and its pinned identities were
reviewed. It does not claim whole-binary licence coverage, and no rebuilt or
relinked binary is produced or asserted. The LGPL components are recorded by
exact source identity only (oven-sh/WebKit and oven-sh/tinycc commits), with the
upstream relink instructions retained rather than any prebuilt object files.

The full source archive is declared as a material by URL and digest but is a
download cache artifact: it is never committed, and packaging must not embed it.

The descriptor contains `mode` (`release` or `controlled-preview`), `target`
(currently only `darwin-arm64`), `archive`, `authority`, and `authoritySha256`.
Paths in both descriptor and authority file records are resolved relative to the
**descriptor** directory. Archive and executable digests and source commit are
reused from the CLI's existing Bun 1.4.2 original-source provenance index; the
current process executable is never substituted for the official archive.

Authority JSON contains `schemaVersion: 1`, `version`, `target`,
`executableSha256`, `sourceCommit`, `assessment`, and `files`. Each file record
contains `path`, `sha256`, original `sourceUrl` (HTTPS), and `kind` (`license`,
`source`, `relink`, or `assessment`). The assessment supplies `status` (`pending`
or `verified`), `reviewer`, and `applicableRequirements` (material kind names).
Findings should describe the requirements established by the actual originals;
the producer does not infer legal obligations from library names.

A release requires an explicit verified authority assessment, reviewer, original
Bun root LICENSE matching the existing pin, source/relink/assessment materials,
and every declared requirement. These are build evidence supplied for review,
not legal conclusions generated by the script. Controlled preview may retain a
pending assessment; its receipt always records legal/release qualification as
false. The earlier JS-prefix notice assessment is not binary-runtime approval.
Original authority and supplied materials are retained under `licenses/bun` with
source URLs and hashes. Missing or changed inputs fail before runtime promotion.

The receipt reports exactly what admission proved. `releaseQualified` and
`declaredMaterialSetVerified` are true only for an admitted release set, meaning
the declared originals, their pinned identities and their digests were verified.
`legalComplete` is always `false` with `legalStatus: 'not-assessed'`: this
producer does not assert whole-binary legal coverage, and no rebuilt or relinked
binary is produced or claimed.

Small fixture archives test admission, failure and selection only; they are not
executed as Bun. Real acceptance must bind the merged source commit, official
archive, extracted runtime, normal installed CLI and module inventories, and
actual `.app` behavior with system Node/Bun absent from PATH. Real release
qualification also needs review of the supplied original materials.

## Signing and final runtime evidence

The producer receipt is explicitly **pre-sign**. `afterPackAdhocSign` uses
`codesign --force --deep --sign -`, which can change Mach-O signature metadata.
The official archive member hash must not be advertised as the final signed
`.app` runtime hash, and no receipt may be written into the app after signing.

After normal packing/signing, run:

`bun desktop/scripts/verify-signed-runtime.ts /path/Xpod.app /outside/app/evidence.json /private/empty-home`

This checks strict signatures, uses the RuntimeManager packaged resolver to
select the app's absolute Bun and normal CLI paths, probes revision, SQLite,
CLI help and module-list with empty PATH, rechecks signatures, and records the
**final** binary/CLI hashes outside the app. Original pre-sign authority remains
sealed and unchanged. The selected runtime must stay inside the app.

This probe does not launch RuntimeManager's service process or a real Electron
window. Its evidence explicitly marks both unverified. The subsequent real-app
acceptance must use RuntimeManager itself with isolated data, accepted modules,
and no system Node/Bun in PATH, verify child command identity, health/readiness
and owned shutdown. Testing a cached source binary cannot qualify that layer.

Evidence output requires an existing private, owned directory outside the app.
The macOS verifier opens that directory without following a symlink, verifies
its device/inode, and creates an exclusive 0600 output via `openat` relative to
the held directory. It retains the file descriptor through all probes and
writes through that descriptor. Replacing the parent pathname cannot redirect
the write into the app; detected replacement fails with an empty recovery file
retained at the original object. No failure cleanup follows the changed path.
The build-only helper uses Bun's embedded C compiler for a fixed-signature
`openat` shim, so C handles macOS variadic ABI correctly; no product runtime
addon, downloaded compiler, or new native distribution is introduced.

Pre-sign authority must match the existing pinned target, version, source
commit, revision, archive digest and required 64-hex executable digest. Missing
or malformed identity fails before creating an evidence output.
